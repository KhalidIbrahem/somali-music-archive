## Key question 1 — Pane layout: resizable/collapsible split panes, docking, SSR, keyboard, persisted layouts, "screensets"

### Takeaway
For a fixed five-region studio (library left, arrange centre, inspector right, editors drawer bottom, transport top) use `react-resizable-panels` v4 (pixel sizing, `role="separator"` keyboard resizing, `defaultLayout`/`onLayoutChanged` persistence, React 19 peer, released weekly); add `dockview-react` only if users must tear panes off into tabs, floating groups or popout windows. Store "screensets" the way Logic does: numbered presets (1–99) that capture window/pane state and zoom and are auto-saved on switch.

### Cited Findings
- `react-resizable-panels`: MIT, 5.5k stars, 2 open issues on the captured page; v4 components are `Group`, `Panel`, `Separator` plus `Grid`, `Cell`, `Gridline`, `Workspace`, `TabCloseButton`; numbers are pixels, unit-less strings are percentages, and px/em/rem/vh/vw are accepted; `collapsible` panels collapse below `minSize` with `collapsedSize` (default 0 %) and `collapsedThreshold`; imperative `collapse()`, `expand()`, `isCollapsed()` — [GitHub README](https://github.com/bvaughn/react-resizable-panels)
- Persistence: `Group`/`Grid` accept `defaultLayout`; docs recommend `onLayoutChanged` to save to storage, keyed by Panel `id`; the README warns of layout shift when server-rendering percentage-based default sizes, `Workspace` has a `serverRenderTabContent` prop, and Gridlines may shift during hydration — [GitHub README](https://github.com/bvaughn/react-resizable-panels)
- Keyboard: Separators render `role="separator"` with WAI-ARIA properties and "improve keyboard accessibility"; Workspace separators are keyboard-resizable — [GitHub README](https://github.com/bvaughn/react-resizable-panels)
- v3→v4 breaking changes (third-party migration guide): `PanelGroup`→`Group`, `PanelResizeHandle`→`Separator`, sizes moved from percentages to pixels, `order`, `onCollapse`/`onExpand` removed, `autoSaveId` replaced by `useDefaultLayout` — [skills.sh migration note](https://skills.sh/wenerme/ai/react-resizable-panels-v3-to-v4); a Dependabot PR shows 3.0.5→3.0.6 in September 2025 — [coder PR #291](https://github.com/bastosmichael/coder/pull/291)
- `dockview`: zero-dependency core with React/Vue/Angular bindings; tabs and groups with drag-and-drop docking, floating groups, popout windows, Splitview/Gridview/Paneview, serialisation ("full layout management"), touch/mobile support, Shadow DOM support, themeable (`themeDark` in the example); 3.5k stars, 72 open issues, 3,826 commits; "Everything is MIT except `dockview-enterprise`, which is proprietary" — [GitHub](https://github.com/dockview/dockview); `api.toJSON()` / `api.fromJSON()` for persisted layouts — [dockview.dev](https://dockview.dev/docs/overview/introduction)
- `allotment`: "derived from the same codebase" as VS Code's split view; snap-closed panes, nesting, show/hide, "persist sizes across reloads"; requires React 17/18/19; MIT; 1.3k stars — [GitHub](https://github.com/johnwalley/allotment); API: `onChange(sizes: number[])`, `defaultSizes`, `preferredSize`, `snap` (default false), `minSize` default 30, `maxSize` default Infinity, `priority` (LayoutPriority) decides which panes resize first, ref handle for programmatic resize; panes need a parent with a height; the docs site had a "server rendering and Next.js" how-to but the fetched pages did not include its text — [allotment docs](https://allotment.mulberryhousesoftware.com/)
- `rc-dock`: dock/float/maximize, popup into a new browser window, `saveLayout()`/`loadLayout()` on plain `LayoutData`/`BoxData`/`PanelData`/`TabData`, controlled (`layout`) and uncontrolled (`defaultLayout`) modes, `loadTab`/`updateTab`/`dockMove`, light/dark SCSS themes; Apache-2.0; 815 stars, 28 open issues; no ARIA/keyboard documentation — [GitHub](https://github.com/ticlo/rc-dock)
- `react-mosaic`: N-ary tiling tree with drag-to-resize/rearrange, tabs as a node type, controlled (`value`/`onChange`) or uncontrolled (`initialValue`), built on react-dnd (HTML5 + touch backends), CSS variables theming, React 16–19, Apache-2.0, 4.8k stars; no accessibility notes — [GitHub](https://github.com/nomcopter/react-mosaic)
- `golden-layout`: last npm publish 2.6.0 on 2022-09-26 — [npm registry](https://registry.npmjs.org/golden-layout); a community React wrapper describes the original as apparently abandoned — [@annotationhub/react-golden-layout](https://www.npmjs.com/package/%40annotationhub%2Freact-golden-layout)
- Logic Pro screensets: a screenset stores "display size, zoom levels, window position, the relationship between the Tracks area and editor, and whether the inspector and Browsers or List Editors areas are open"; numbered 1–99; recall by typing the number (hold Control for two digits), from the Screenset menu, or Next/Previous Screenset key commands; "You don't need a save command. Your current view is stored as the current screenset whenever you switch to another one"; a MIDI meta event 49 can switch screensets at a playhead position — [Apple Logic Pro help (10.1)](https://help.apple.com/logicpro/mac/10.1/en.lproj/lgcp9bbbcb23.html); Logic also lets you protect, copy, rename, delete, import and revert screensets — [Apple Logic Pro User Guide](https://support.apple.com/guide/logicpro/screensets-overview-lgcp5cbf18ca/mac)
- Signal (the open-source React sequencer) uses its own `@ryohey/react-split-pane` (0.1.94, published 2022-06-26) — [Signal app/package.json](https://raw.githubusercontent.com/ryohey/signal/main/app/package.json), [npm registry](https://registry.npmjs.org/@ryohey/react-split-pane)

### Inferences
- Recommended: `react-resizable-panels` 4.x for the five fixed regions (one horizontal `Group` of library | centre | inspector, nested vertical `Group` of arrange | editors drawer; transport outside the groups). Use pixel `minSize` (e.g. 240 px library, 280 px inspector, 160 px drawer) and `collapsible` with `collapsedSize` 0 so a double-click/shortcut can hide a pane; persist via `onLayoutChanged` into the project document, not only localStorage.
- SSR: because the README warns about hydration layout shift with percentage defaults and the whole studio needs `AudioContext`, render the studio shell as a `'use client'` component loaded with `next/dynamic` `{ ssr: false }` (see Key question 10), or pass a pixel `defaultLayout` read from a cookie so server and client agree.
- "Screensets" = a JSON preset `{ panes: Record<paneId, {size, collapsed}>, zoom: {pxPerBeat, trackHeight}, visibleEditors, selectedTool }` stored per project with slots 1–9 bound to digit keys (Logic uses digits; conflicts with musical typing are discussed in Key question 6). Auto-save the active slot on switch, exactly as Logic does, and keep a "protected" flag per slot.
- Reach for `dockview-react` (tabs, floating, popout windows, `toJSON`) only for a "detach the mixer/piano roll to a second monitor" feature; it adds its own theming and has no documented keyboard model, so budget a11y work. `golden-layout` is out (no release since 2022); `rc-dock`/`react-mosaic` are maintained but lack ARIA documentation.

### Gaps
- Could not retrieve the react-resizable-panels v4 docs site body or the package README/CHANGELOG via raw.githubusercontent (404 at the guessed paths), so the exact Separator key bindings (arrows / Home / End / Enter) and the `useDefaultLayout` cookie recipe are unverified beyond the README summary.
- The allotment "server rendering and Next.js" guide text was not retrieved.
- No source documents keyboard accessibility for dockview, rc-dock or react-mosaic.

## Key question 2 — Timeline/arrange rendering at scale: DOM vs Canvas 2D vs WebGL/WebGPU, virtualisation, DPR, OffscreenCanvas, rAF playhead, pointer drags, marquee, pinch-zoom, scroll sync, frame-time figures

### Takeaway
Keep regions as DOM for hit-testing/a11y but virtualise tracks (TanStack Virtual) and cull off-screen clips; move the heavy per-pixel layers (waveforms, grid, meters, selection indicators) to Canvas 2D sized by `devicePixelRatio`, and drive the playhead from one `requestAnimationFrame` loop that writes a transform directly, never through React state. Published figures: tldraw culls a 10,000-shape page to ~50 rendered DOM shapes and got "up to 25x" faster indicators by moving them from SVG to canvas; monday.com found DOM cells could not reach 60 fps even when empty; PixiJS v8 reports ~0.12 ms CPU for 100k static sprites.

### Cited Findings
- Frame budgets: RAIL says produce each animation frame in 10 ms or less because the 16 ms frame at 60 fps includes ~6 ms of browser work; process input in 50 ms to respond within 100 ms; dragging, panning and pinch-zoom count as animation (10 ms budget) — [web.dev RAIL](https://web.dev/articles/rail); INP "good" is ≤ 200 ms at the 75th percentile, only clicks/taps/key presses count — [web.dev INP](https://web.dev/articles/inp)
- DOM ceiling (measured): monday.com's board moved from 30 to 45 fps with lighter DOM during scroll, then concluded "it was not possible to reach 60fps while using DOM based cells" even with empty cells; a canvas POC drew ~4× as many cells and was still faster; their budget arithmetic: at 0.2 ms per cell, 200 cells ≈ 40 ms/frame (~25 fps), so each cell must draw in < 0.05 ms for 60 fps; techniques: canvas layered above DOM, sticky screen-sized canvas (a board-sized canvas crashed the browser), frame skipping when nothing changed, offscreen caching of repeated glyphs, frame-count debounce, Cypress screenshot parity checks — [monday.com engineering, part 2](https://engineering.monday.com/the-power-of-the-canvas-api-a-deep-dive-into-how-we-transformed-our-table-performance-at-monday-com-part-2)
- DOM with culling (tldraw): a spatial index hides off-screen shapes with `display: none`, so "a canvas with 10,000 shapes might only render 50"; debounced zoom activates above 500 shapes (`debouncedZoomThreshold`); `maxShapesPerPage` default 4000; LOD (text shadows off below 0.35 zoom, dashed strokes rendered solid); `editor.performance` emits `interaction-end` with `fps` and `p95FrameTime` — [tldraw performance](https://tldraw.dev/sdk-features/performance); v4.4 moved selection/hover indicators from SVG to 2D canvas for "up to 25x faster rendering in some scenarios" with many selected/hovered shapes, added an R-tree (RBush) for O(log n) brushing/selection/erasing, and skips hover hit-testing while panning — [tldraw v4.4.0 release](https://tldraw.dev/releases/v4.4.0)
- GPU batching (PixiJS v8, Bunnymark, hardware unspecified): 100k moving sprites ~50 ms→~15 ms CPU (v7→v8), ~9 ms→~2 ms GPU; 100k static sprites ~21 ms→~0.12 ms CPU; changing scene structure ~50 ms→~24 ms; "WebGPU does not automatically guarantee improved performance over WebGL in all scenarios", it helps with many batch breaks (filters, masks, blend modes); released 2024-03-05 — [PixiJS v8 launch](https://pixijs.com/blog/pixi-v8-launches)
- Figma's renderer is C++ compiled to WebAssembly with WebGL and WebGPU backends (Dawn), falls back from WebGPU to WebGL mid-session on failure; "performance improvement when using WebGPU on some classes of devices", neutral on others, no regressions; async readback could add "hundreds of milliseconds" to load — [Figma blog, 2025-09-18](https://www.figma.com/blog/figma-rendering-powered-by-webgpu/)
- Idle cost of canvas apps (measured on an i5-1035G7 Surface, Chromium, median of 5 runs, CDP `Performance.metrics`): Figma ~3.49 % idle CPU, Excalidraw ~1.18 %, Skedoodle ~0.09 %; tldraw's `TickManager` runs a rAF loop every frame without a dirty flag; Excalidraw's idle cost comes from hover/tool/pointer position living in React state (diff + store commit + `onChange` listeners per update); fixes: render only after user-driven changes, throttle non-interactive updates, keep an unthrottled path for direct drags — [dev.to analysis](https://dev.to/eugenioenko/why-your-drawing-app-uses-2-cpu-when-youre-not-using-it-10e0)
- Virtualisation: `@tanstack/react-virtual` is headless, vertical/horizontal/grid; options relevant to a track list: `horizontal`, `lanes`, `overscan` (default 1), `scrollMargin` (offset origin when a ruler sits above the list; subtract it in absolute-position transforms), `paddingStart/End`, `gap`, `estimateSize`, `measureElement` (ref + `data-index` for variable track heights), `resizeItem`, `scrollToIndex` (`align`, `behavior`), `useScrollendEvent` (default false; fallback `isScrollingResetDelay` 150 ms), `rangeExtractor` for sticky rows; memoise `getItemKey`; `useAnimationFrameWithResizeObserver` adds ~16 ms delay — [TanStack Virtualizer API](https://tanstack.com/virtual/latest/docs/api/virtualizer), [intro](https://tanstack.com/virtual/latest/docs/introduction); Signal uses `react-window` 2.2.7 — [Signal pnpm catalog](https://raw.githubusercontent.com/ryohey/signal/main/pnpm-workspace.yaml)
- DPR-correct canvas: set `canvas.style.width/height` in CSS px, `canvas.width/height = Math.floor(size * devicePixelRatio)`, then `ctx.scale(dpr, dpr)`; a `(resolution: Xdppx)` `matchMedia` listener re-runs when the ratio changes (zoom, display move) — [MDN devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio); wavesurfer notes canvas memory scales with width × height × DPR², so a 256 px-tall waveform on 2× uses 4× the memory — [wavesurfer performance](https://wavesurfer.xyz/docs/performance/)
- OffscreenCanvas: `transferControlToOffscreen()` + `postMessage` with transfer list lets a worker draw; web.dev reports only qualitative gains ("some speed improvements", worker animation keeps running while the main thread is busy); support Chrome 69, Edge 79, Firefox 105, Safari 16.4; workers have no DOM; the old `commit()` is deprecated in favour of `requestAnimationFrame` in the worker — [web.dev OffscreenCanvas](https://web.dev/articles/offscreen-canvas); Evil Martians report Lighthouse Performance 95→100 after moving Three.js to an OffscreenCanvas worker (no methodology) — [Evil Martians](https://evilmartians.com/chronicles/faster-webgl-three-js-3d-graphics-with-offscreencanvas-and-web-workers); a DEV article's "30 fps → 60 fps" claim has no methodology (anecdotal) — [dev.to](https://dev.to/jeevankishore/enhancing-graphics-performance-with-offscreencanvas-and-d3js-19ka)
- rAF playhead: a playback-system rewrite found reading/writing time through React state restarted the loop on each render and made the playhead jump; the fix was a time ref updated per frame with state set only for infrequent display — [dev.to playback rewrite](https://dev.to/therealgabry/playback-system-complete-rewrite-2lnm); Zustand's "transient updates" pattern: `subscribe` a slice into a `useRef` inside `useEffect` and mutate the view directly, which "can greatly improve performance" — [Zustand README](https://github.com/pmndrs/zustand)
- Pointer drags: `setPointerCapture(pointerId)` retargets subsequent pointer events to the capturing element even when the pointer leaves it; capture ends on `releasePointerCapture()` or `pointerup`; MDN's slider example sets `touch-action: none` — [MDN setPointerCapture](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture); `touch-action: none` disables browser panning/zooming, `manipulation` = `pan-x pan-y pinch-zoom` and removes double-tap zoom and the click delay; an app receives `pointercancel` when the browser takes over a gesture — [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action)
- Pinch on touch: cache events by `pointerId`, compute `Math.hypot` between two pointers on `pointermove`, compare with the previous distance, reset when fewer than two pointers remain, and set `touch-action: none` — [MDN pinch-zoom gestures](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events/Pinch_zoom_gestures)
- Pinch on trackpads: browsers send a simulated `wheel` event with `ctrlKey === true` for trackpad pinch — [MDN MouseEvent.ctrlKey](https://developer.mozilla.org/en-US/docs/Web/API/MouseEvent/ctrlKey); Chrome since M35, Firefox 55; Safari uses proprietary `gesturestart/gesturechange` — [kenneth.io](https://kenneth.io/post/detecting-multi-touch-trackpad-gestures-in-javascript); Ctrl+mouse-wheel also sets `ctrlKey`, and Mappedin distinguishes devices by timing ("event bursts are always trackpads … single events more than 20ms apart, it's a mouse wheel") — [Mappedin](https://www.mappedin.com/resources/blog/why-panning-and-zooming-in-a-web-app-cant-be-perfect/); `@use-gesture/react` (10.3.1, 2024-03-21, MIT) wraps drag/pinch/wheel/scroll/move/hover, handles two-pointer pinch, trackpad pinch via Ctrl+wheel, and Safari gesture events through a `target` ref, and documents the `touch-action` requirement — [use-gesture docs](https://use-gesture.netlify.app/docs/gestures/), [npm registry](https://registry.npmjs.org/@use-gesture/react)
- Signal renders its editors with `@ryohey/webgl-react` (0.7.1): instanced WebGL 2 (fallback 1) rectangles/bordered rectangles/circles in pixel coordinates, `HitArea` for pointer/wheel events, `Transform` with gl-matrix; 18 stars — [GitHub](https://github.com/ryohey/webgl-react), [Signal app/package.json](https://raw.githubusercontent.com/ryohey/signal/main/app/package.json)
- Multi-layer canvas pattern (static layer drawn once, dynamic layer redrawn) is documented generically — [dev.to multi-layer canvas](https://dev.to/iprajapatiparesh/unlocking-60fps-charts-multi-layer-canvas-in-react-3cpl)

### Inferences
- Target architecture for the existing arrange view: (1) TanStack Virtual for track rows (variable `estimateSize` by track height; `scrollMargin` = ruler height); (2) one `<canvas>` per visible track lane for waveform/MIDI preview, DPR-scaled, redrawn only when zoom/scroll/data change (dirty flag, as monday.com and the idle-CPU study recommend); (3) regions stay as absolutely positioned DOM elements so they can be focusable (`role="option"`/`gridcell`) and keep the existing pointer drags; (4) selection outlines, marquee rectangle and snap guides on one overlay canvas (the tldraw 4.4 lesson); (5) playhead and meters updated in a single rAF loop writing `style.transform` and canvas pixels from `AudioContext.currentTime`, never via `setState`.
- Scroll sync between ruler, track headers and lanes: use a single scroll container for lanes and mirror its `scrollLeft`/`scrollTop` to the ruler and headers inside the same rAF tick (`transform: translateX(-scrollLeft)`), so there is one scroll event per frame; this is a pattern inference, no published source found.
- Marquee selection and snapping: keep an R-tree (tldraw uses RBush) of region bounds per track for O(log n) brushing; snapping to grid/other region edges is an inference (no source) — compute candidate edges once at drag start and quantise in the move handler.
- Pinch-zoom: handle `wheel` with `ctrlKey` as zoom around the cursor (`preventDefault` with a non-passive listener), two-pointer distance on touch, and Safari `gesture*` via `@use-gesture` if Safari trackpad pinch matters; set `touch-action: none` on the lanes and `pan-y` on the track header column.
- WebGL/PixiJS is only warranted if thousands of simultaneous regions plus dense MIDI previews exceed the Canvas 2D budget; `@pixi/react` 8 requires React 19, which the target stack has. `regl` has not been released since 2024-11.

### Gaps
- No published frame-time figures exist for any web DAW arrange view; the figures above come from whiteboard/table apps and a sprite benchmark.
- No source documents a canonical ruler/header/lane scroll-sync pattern or snapping algorithm for web DAWs.
- Excalidraw's own renderer code (static vs dynamic canvas) was not read from the primary repository; only the third-party idle-CPU analysis is cited.

## Key question 3 — Waveform rendering: wavesurfer.js, peaks.js, waveform-data.js, min/max peak pyramids, workers, thousands of clips at 60 fps

### Takeaway
Do not embed one wavesurfer instance per clip; compute a min/max peak pyramid per audio file once in a worker (power-of-two samples-per-pixel levels, each derived from the previous), cache it, and draw clip slices onto per-lane canvases. wavesurfer.js 8 (BSD-3) and peaks.js 4 (LGPL-3) are useful for the single-file audio editor view, and their docs give the memory limits to respect (8,000 px max canvas width, ~1,000–2,000 points per channel, 60 min stereo decode > 500 MB).

### Cited Findings
- wavesurfer.js performance guidance: decoding "allocates the entire file as raw PCM in memory", a 60-minute stereo track can exceed 500 MB; use the MediaElement backend plus pre-computed `peaks` and `duration`; 1,000–2,000 points per channel suits players; the waveform is split across canvases of at most 8,000 px (`MAX_CANVAS_WIDTH`), each also capped at the container `clientWidth`; off-screen canvases are cleared once `MAX_NODES = 10` is exceeded; nothing renders if the container width is 0; "waveforms tens of thousands of pixels wide can crash the tab"; each region is an absolutely positioned DOM element and thousands cause glitches — "for very dense data, consider a custom canvas overlay" — [wavesurfer performance](https://wavesurfer.xyz/docs/performance/)
- wavesurfer.js v8.0.0 (released 23 Sep, 2026 per registry): `destroy()` is final, replaced loads reject with `AbortError`, `normalize: true` scales by whole-file peak to remove seams, the decoder no longer mutates passed-in peaks, seam/zoom/cursor-drift fixes, GC leak test suite in CI, `definePlugin()` functional plugin API, windowed spectrogram with a 256 MB byte cache; 8.0.3 made the Renderer view audio instead of copying and reduced Regions/Scroll/Timeline to one pass per event — [wavesurfer releases](https://github.com/katspaugh/wavesurfer.js/releases), [npm registry](https://registry.npmjs.org/wavesurfer.js); the maintainers recommend bbc/audiowaveform for generating peaks for large files — [wavesurfer docs mirror](https://tessl.io/registry/tessl/npm-wavesurfer-js/7.10.0/files/docs/audio-processing.md)
- peaks.js: HTML canvas via Konva (peer), zoomable/scrollable views, segments and points, accepts audiowaveform binary `.dat` (use `-b 8`; 16-bit unsupported) or JSON, or computes in-browser from an `AudioBuffer` ("suits short files … CPU-intensive"); LGPL-3.0; "Ongoing development of this project has moved to" Codeberg; 62 open issues; React example `chrisn/peaksjs-react-example` — [GitHub](https://github.com/bbc/peaks.js); 4.0.0 published 2025-08-30 with peers konva ≥ 8.3.14 < 10 and waveform-data ≥ 4.5.2 < 5 — [npm registry](https://registry.npmjs.org/peaks.js)
- Peak pyramids: a Stack Overflow answer describes the mipmap approach — precompute min/max at power-of-two samples-per-pixel scales, derive each level from the previous one rather than raw samples, and interpolate between the two nearest levels when rendering ("basically a 1D Mipmap") — [Stack Overflow 71423858](https://stackoverflow.com/a/71423858); the Rust `timestretch` crate builds a three-band (200 Hz / 2 kHz Butterworth crossovers) min/max pyramid at 150 buckets/s halved down to ~1024 buckets, with tests that halving keeps global extrema — [docs.rs timestretch waveform.rs](https://docs.rs/crate/timestretch/latest/source/src/analysis/waveform.rs); the Rust `waveform` crate advertises "multilevel binning for different zoom levels" — [crates.io waveform](https://crates-io.ganymede-static.progval.net/crates/waveform/0.2.0)
- Worker transport: `comlink` 4.4.2 (Apache-2.0, 2024-11-07) for RPC to a peaks worker — [npm registry](https://registry.npmjs.org/comlink); OffscreenCanvas in workers (support Safari 16.4+) — [web.dev](https://web.dev/articles/offscreen-canvas)
- Signal's package list includes `wav-encoder` and `@breezystack/lamejs` for export, no waveform library — [Signal app/package.json](https://raw.githubusercontent.com/ryohey/signal/main/app/package.json)

### Inferences
- Pipeline for the target app: on import, decode once (or stream via MediaElement for previews), post the `Float32Array` channels to a worker, build levels at 1, 2, 4 … 2^k samples per bucket as `Int8Array`/`Int16Array` min/max pairs (8-bit is what audiowaveform's `-b 8` uses and peaks.js requires), store the pyramid in OPFS/IndexedDB keyed by file hash, and keep only the two levels nearest the current zoom in memory. Per-clip draw = slice of the level (start/end sample → bucket indices) into the lane canvas; at 60 fps with dirty-flag redraws, thousands of clips are bounded by visible pixels, not clip count (this follows from the monday.com cell budget; no DAW-specific figure exists).
- Use wavesurfer 8 or peaks.js 4 only for the dedicated sample/audio editor drawer (regions, trimming) where a single file is shown; peaks.js' LGPL-3 is acceptable for dynamic linking in a web bundle but should be checked against the project licence policy (Apache-2.0 repo).
- Respect wavesurfer's own limits in a custom renderer: never allocate a canvas wider than the viewport; height × DPR² drives memory.

### Gaps
- No published measurement of waveform frames-per-second or draw time for thousands of clips in any web DAW; the Ardour commit "completely rethink waveform rendering (again)" exists but its body was not read — [Ardour commit](https://git.ardour.org/ardour/livetrax/commit/437099fff982a40d479f275c2f7eedd857996330).
- No source confirms a worker-based peak pipeline in wavesurfer or peaks.js (both compute on the main thread or expect precomputed files).

## Key question 5 — Controls: knobs, faders, VU/peak meters, LCD displays; accessible range inputs with fine/coarse and double-click reset; 60 fps meters

### Takeaway
Build knobs and faders as ARIA sliders (`role="slider"`, `aria-valuenow/min/max/text`, `aria-orientation`, arrows ±1 step, Home/End, Page Up/Down for coarse steps) on top of pointer capture; `react-knob-headless` 0.4.0 is the only maintained React primitive but its peer range stops at React 18 and it ships no keyboard handling. Meters belong on canvas or `transform: scaleY()` in the rAF loop; LCD timecode needs `font-variant-numeric: tabular-nums`.

- `react-dial-knob` 1.3.0 (2021-01-31, peer react ^17.0.1) — [npm registry](https://registry.npmjs.org/react-dial-knob)

- Radix `@radix-ui/react-slider` 1.6.1 (2026-10-12, MIT, React 16.8–19) is the slider primitive Signal uses (1.3.6 in its catalog) — [npm registry](https://registry.npmjs.org/@radix-ui/react-slider), [Signal pnpm catalog](https://raw.githubusercontent.com/ryohey/signal/main/pnpm-workspace.yaml)
- Tabular figures: `font-variant-numeric: tabular-nums` activates "figures where numbers are all of the same size, allowing them to be easily aligned" (OpenType `tnum`); `lining-nums` (`lnum`), `slashed-zero` (`zero`) — [MDN font-variant-numeric](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric); a design-system utility recommends tabular figures for timers to prevent layout shift of changing content — [Dialpad Dialtone](https://dialtone.dialpad.com/utilities/typography/font-variant-numeric.html)

### Inferences
- Knob/fader recipe for the target app (no library needed): `role="slider"` div, `tabIndex=0`, pointer capture on `pointerdown`, vertical drag delta → value with a pixel-per-unit constant; Shift (or Cmd/Ctrl) multiplies the step by 0.1 for fine mode (inference: fine/coarse modifiers are DAW convention; the APG only standardises Page Up/Down as the coarse step); double-click or Alt-click resets to default (inference from DAW convention, not a WAI pattern); keyboard arrows ±1 step, Page Up/Down ±10 steps, Home/End; `aria-valuetext` carries "−6.0 dB" or "L 23"; ensure the hit area is ≥ 24 × 24 CSS px even if the drawn knob is 18 px.

- LCD transport display: a `<output>` with `tabular-nums lining-nums slashed-zero` and `aria-live="off"` (updates every frame would spam screen readers), updated through a ref from the rAF loop.

### Gaps

## Key question 6 — Keyboard handling: shortcut systems, physical-key vs character matching, musical typing conflicts, text-field focus; menus and context menus

### Takeaway
Match shortcuts on `KeyboardEvent.code` (layout-independent physical keys) for letter/digit/WASD-style bindings and on `key` for symbol bindings; `tinykeys` 4.0.1 (~650 B–1 KB, MIT) accepts both (`"d"` matches `key`, `"KeyD"` matches `code`) and ignores inputs by default, while `react-hotkeys-hook` 5.3.3 adds scopes, `enableOnFormTags` and a `useKey` toggle. Use Radix Menubar/ContextMenu (roving tabindex, typeahead, WAI-ARIA menu pattern) and `cmdk` 1.1.1 for a command palette; keep a single "musical typing" scope that is enabled only when the arrange/piano roll has focus and no text field is active.

### Cited Findings
- `KeyboardEvent.code` "represents a physical key on the keyboard (as opposed to the character generated by pressing the key)" and "isn't altered by keyboard layout or the state of the modifier keys"; `KeyQ` is Q on QWERTY, `'` on Dvorak and A on AZERTY, so `code` cannot name the key for the user; use `code` for position-based controls (WASD), `key` for the produced character — [MDN KeyboardEvent.code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code); `code` values are named after the en-US layout — [W3C www-dom thread](https://lists.w3.org/Archives/Public/www-dom/2013JanMar/0190.html); Red Blob Games summarises: `key` to match the layout, `code` to match physical location — [Red Blob Games](https://www.redblobgames.com/x/2324-keyboard/); Dokploy switched modifier shortcuts to `event.code` because AZERTY's physical Q reports `key === "a"` — [Dokploy PR #3748](https://github.com/Dokploy/dokploy/pull/3748); Ctrl+[ / Ctrl+] change drastically between US, German and Latin American layouts — [keyboard-i18n](https://npmjs.org/package/keyboard-i18n)
- `navigator.keyboard.getLayoutMap()` returns a map from physical codes to the current layout's strings (`get("KeyW")` → "w" on QWERTY) so UIs can show correct labels; experimental, limited availability, secure context only — [MDN Keyboard.getLayoutMap](https://developer.mozilla.org/en-US/docs/Web/API/Keyboard/getLayoutMap)
- `tinykeys`: matches `KeyboardEvent.key` and `KeyboardEvent.code` (`"d"` vs `"KeyD"`, case-insensitive), sequences (`"g i"`, timeout 1000 ms), `$mod` = Meta on Mac / Control elsewhere, optional modifiers `[Shift]+D`, regex keys `$mod+([0-9])`, ignores `input`/`textarea`/`select`/`[contenteditable]` unless the element is the `currentTarget` (configurable via `options.ignore`), bindings checked in declaration order, MIT, "~650 B" (About) vs "~1KB" (README) — [GitHub](https://github.com/jamiebuilds/tinykeys); 4.0.1 published 2026-09-25 — [npm registry](https://registry.npmjs.org/tinykeys)
- `react-hotkeys-hook` 5.x `useHotkeys` options: `enabled`, `enableOnFormTags` (default false; array of tags allowed), `enableOnContentEditable`, `ignoreModifiers`, `preventDefault`, `keydown`/`keyup`, `scopes` (default `'*'`, toggled via `HotkeysProvider`), `splitKey` `'+'`, `delimiter` `','`, `useKey` (default false: "Matches the character the user's layout produces instead of the physical key code"), `description`, `ignoreEventWhen`, `sequenceTimeoutMs` 1000, `sequenceSplitKey` `'>'`; docs give the `#` on US vs German example and recommend `ignoreModifiers`/`useKey` for symbol shortcuts — [react-hotkeys-hook docs](https://react-hotkeys-hook.vercel.app/docs/api/use-hotkeys); hotkeys scoped to non-interactive elements need a `tabIndex` — [docs mirror](https://docsearch.algolia.com/mcp/docs/repo/johannesklauss/react-hotkeys-hook)
- `hotkeys-js`: ~8 kB min / 3.8 kB gzip, no deps, scopes (`setScope`/`getScope`/`deleteScope`, `all` always active), default filter skips INPUT/SELECT/TEXTAREA (`hotkeys.filter` override), `keyup` option, `splitKey`, `getPressedKeyCodes`/`getPressedKeyString`; examples use numeric key codes (`[17, 65]`), suggesting keyCode-based matching; tested back to IE6 — [GitHub](https://github.com/jaywcjlove/hotkeys-js)
- `cmdk`: "Fast, unstyled command menu React component", usable as an accessible combobox, built-in filtering/sorting with a custom `filter` and `keywords`, `Command.Dialog` composes Radix Dialog, `loop` wraps arrow keys, groups get `hidden` when filtered, no virtualisation ("good performance up to about 2,000–3,000 items"), "Labeling, aria attributes, and DOM ordering tested with Voice Over and Chrome DevTools", Playwright suite, 13.1k stars, 54 open issues, MIT — [GitHub](https://github.com/pacocoursey/cmdk); 1.1.1 published 2025-03-14 — [npm registry](https://registry.npmjs.org/cmdk)
- Radix Menubar: follows the WAI-ARIA Menu Button pattern with roving tabindex, "full keyboard navigation and typeahead", submenus with reading direction, checkbox/radio items, collision-aware positioning; keys: Space/Enter activate, ArrowDown/Up move, ArrowLeft/Right move between top-level triggers or open/close submenus, Esc closes and returns focus — [Radix Menubar docs](https://www.radix-ui.com/primitives/docs/components/menubar); W3C's editor menubar example uses roving tabindex with Left/Right wrap-around — [APG menubar example](https://www.w3.org/TR/2021/NOTE-wai-aria-practices-1.2-20211129/examples/menubar/menubar-editor.html); a wrapper recommends `aria-hidden="true"` on shortcut-hint spans so they are not read twice — [Catalyst menubar](https://catalyst-next.pmi.org/docs/primitives/navigation/menubar)
- Toolbar pattern (transport bar): `role="toolbar"`, single tab stop with arrow keys moving between controls (roving tabindex), Home/End optional, `aria-orientation="vertical"` for vertical toolbars, avoid controls that need the same arrow pair (put a textbox last) — [WAI-ARIA APG toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/)
- Logic recalls screensets with digit keys 1–9 (0 is Stop by default) and these recall keys can be reassigned in Key Commands — [Apple Logic Pro help](https://help.apple.com/logicpro/mac/10.1/en.lproj/lgcp9bbbcb23.html)
- Ariakit 0.4.42 (MIT, React 17–19) and react-aria-components 1.22.1 (Apache-2.0) are the maintained alternatives to Radix for menus/sliders — [npm registry](https://registry.npmjs.org/@ariakit/react), [npm registry](https://registry.npmjs.org/react-aria-components)

### Inferences
- Shortcut architecture for the target app: one registry (`id → {code-binding, label, scope, handler}`) feeding both `tinykeys` (or `react-hotkeys-hook` scopes) and the cmdk palette, so every command is discoverable and the palette shows labels resolved through `getLayoutMap()` where available (fallback: show the `code` name). Bind letters/digits by `code` (`KeyA`, `Digit1`), symbols by `key` (`useKey`/`ignoreModifiers` in react-hotkeys-hook).
- Musical typing (A–L as white keys, W/E/T/Y/U as black keys, Z/X octave) must be a separate scope that is active only when a MIDI track is armed and focus is inside the arrange/piano-roll region, because it collides with single-letter tool shortcuts and digit-key screenset recall; `tinykeys`' default `ignore` for inputs already protects text fields, and the registry must disable the musical scope whenever `document.activeElement` is an editable element or a Radix menu is open.
- Menus: Radix Menubar for File/Edit/Track/… with `RightSlot` shortcut hints marked `aria-hidden`; Radix ContextMenu on regions/tracks; typeahead comes for free.

### Gaps
- No source quantifies how DAW web apps resolve musical-typing conflicts; the scope design above is an inference.
- hotkeys-js' internal matching (keyCode vs key) was not confirmed from source.

## Key question 7 — State and undo: immutable project document, patches, store choice, coalescing drags, autosave to IndexedDB/OPFS, blobs, CRDT sync

### Takeaway
Keep the project document as an immutable tree edited with `immer` `produceWithPatches` (patches + inverse patches per command, coalesced per drag gesture) inside a Zustand store (transient subscriptions for the playhead); use `zundo` only if snapshot-based history is acceptable. Persist the document JSON to IndexedDB (Dexie 4 / idb-keyval 6) and audio/peaks blobs to OPFS, request `navigator.storage.persist()`, and plan for Safari's 7-day eviction. For collaboration, Yjs (13.6.33) is the lightest and best-benchmarked CRDT; Automerge 3 fixed its memory story (700 MB → 1.3 MB on Moby Dick); Loro is fastest to parse but least mature.

### Cited Findings
- immer patches: since v6 call `enablePatches()` once; `produce(base, recipe, (patches, inversePatches) => …)` or `produceWithPatches` → `[nextState, patches, inversePatches]`; `applyPatches` replays onto a different base (fork/merge example); patch format is RFC 6902-like with `path` as an array; patches "aren't guaranteed to be minimal" and may need compression — [Immer patches docs](https://immerjs.github.io/immer/patches/); immer 11.2.9 — [npm registry](https://registry.npmjs.org/immer)
- Zustand 5.1.0 (MIT, react ≥ 18; peers immer ≥ 9.0.6 for the middleware): transient `subscribe` into a ref, `useShallow`, `immer` middleware for draft mutation, `persist` with `createJSONStorage(() => storage)` for "any kind of storage" — [Zustand README](https://github.com/pmndrs/zustand), [npm registry](https://registry.npmjs.org/zustand)
- zundo (2.3.0, 2024-11-17, < 700 B, MIT, zustand ^4.3 || ^5): `temporal` middleware with `pastStates`/`futureStates`, `undo(steps)`/`redo(steps)`, `pause()`/`resume()`, `handleSet` wrapper for throttle/debounce "so rapid changes are stored as one history entry" (1000 ms throttle example), `partialize`, `equality`, `diff` (store deltas; return null to skip), `limit`; snapshots are full state by default and recorded on every setter call; no built-in persistence (wrap with `persist` or seed stacks) — [GitHub](https://github.com/charkour/zundo), [npm registry](https://registry.npmjs.org/zundo); a community `@spliu/zustand-immer` stores immer forward/inverse patches but caps history at 10 — [pkgstats](https://www.pkgstats.com/pkg:@spliu/zustand-immer)
- Signal: Jotai for UI state, domain state outside React behind `useSyncExternalStore`, transaction-per-mutation with a single notification, abandoned MobX — [Signal ARCHITECTURE.md](https://github.com/ryohey/signal/blob/main/ARCHITECTURE.md); openDAW: `editing.modify()` transactions with batched notifications at `endTransaction()` — [openDAW lib/box README](https://raw.githubusercontent.com/andremichelle/openDAW/main/packages/lib/box/README.md)
- Yjs UndoManager: `captureTimeout` default 500 ms merges edits inside the window (0 = every change separate), `stopCapturing()` forces a new item, `trackedOrigins` limits undo to chosen transaction origins (remote changes are not undone by default), `stack-item-added/popped` events carry `meta` for cursor restore — [Yjs UndoManager docs](https://docs.yjs.dev/api/undo-manager); Yjs is MIT, 23k stars, 126 open issues, maintained "in my spare time" with paid support; `y-indexeddb` persists updates locally — [GitHub yjs](https://github.com/yjs/yjs)
- CRDT benchmark (B4 real-world trace, i5-8400, Node 20.5): Yjs 13.6.11 parse 39 ms / mem 3.2 MB / doc 159,929 B / encode 11 ms; ywasm 0.9.3 parse 16 ms; Loro 0.10.1 parse 13 ms / doc 258,228 B / encode 77 ms; Automerge 2.1.10 parse 1,805 ms / doc 129,116 B / encode 185 ms; `memUsed` excludes WASM memory and B4 is replayed in one transaction "because Automerge otherwise runs out of memory" — [dmonad/crdt-benchmarks](https://github.com/dmonad/crdt-benchmarks); Automerge 3 (July 2025) cut memory "by over 10x", Moby Dick paste 700 MB → 1.3 MB, a document that had not loaded after 17 hours loads in 9 s, same file format as Automerge 2 — [Automerge 3 blog](https://automerge.org/blog/automerge-3/); secondary handbooks give conflicting Yjs/Automerge timings (1,074 ms vs 1,816 ms; 5,714 ms vs 14,326 ms) so prefer the primary benchmark — [handbook A](https://handbook-hld.pages.dev/curriculum/architecture-patterns/crdt-applications/), [handbook B](https://handbook-hld.pages.dev/curriculum/distributed-systems-theory/crdts/)
- OPFS: origin-private, byte-level, in-place writes; `createSyncAccessHandle()` only in workers with synchronous `read/write/truncate/flush/getSize`; async `createWritable()` on the main thread; Baseline widely available since March 2023; HTTPS required; shares the origin quota with IndexedDB; clearing site data deletes it — [MDN OPFS](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system)
- Quotas/eviction: IndexedDB, Cache and OPFS share one per-origin quota; Chromium up to 60 % of total disk (80 % browser cap); Firefox best-effort min(10 % disk, 10 GiB) and persistent up to 50 %; Safari (macOS 14+/iOS 17+) ~60 % of disk for browser apps, ~15 % for embedded WebViews, cross-origin iframes 1/10 of parent, older Safari 1 GiB then prompt; `navigator.storage.persist()` (Firefox prompts, Safari/Chromium decide silently by engagement); LRU eviction under pressure skips persistent origins; **Safari deletes script-created storage for origins with no click/tap interaction in the last 7 days of browser use**; writes over quota throw `QuotaExceededError`; `navigator.storage.estimate()` for usage — [MDN storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
- Dexie 4.4 offloads Blob/File/ArrayBuffer ≥ 4 KB to blob storage during Dexie Cloud sync (a sync feature, not local storage); 4.4.7 published 2026-10-19, Apache-2.0 — [Dexie blog](https://dexie.org/blog/dexie-44-dexie-cloud-server-30-the-big-one), [Dexie blob offloading](https://dexie.org/docs/cloud/blob-offloading), [npm registry](https://registry.npmjs.org/dexie); idb-keyval 6.3.0 (2026-07-08, Apache-2.0) is the minimal promise wrapper — [npm registry](https://registry.npmjs.org/idb-keyval), [GitHub](https://github.com/HenrikJoreteg/idb-keyval); openDAW bundles projects with jszip and has "cloud backups" and "Live Rooms" — [openDAW README](https://github.com/andremichelle/openDAW)

### Inferences
- Document model: `Project = { tracks, regions, clips, notes, automation, mixer, markers }` as normalised maps keyed by UUID; every user command is `(draft) => void` run through `produceWithPatches`; the history entry stores `{patches, inversePatches, label, ts}`. Coalescing: start a gesture (`beginGesture(label)`), accumulate patches in a pending entry during `pointermove`, commit on `pointerup` — this gives one undo step per drag, like Yjs' `captureTimeout`/`stopCapturing` and zundo's `handleSet` throttle but deterministic. Patches are small enough to persist as an op-log for autosave and crash recovery; zundo's full-snapshot default is wasteful for a 10k-note project.
- Store choice: Zustand (transient subscriptions for playhead/meters, `useShallow` for inspector panels) or Jotai (Signal's choice) for UI state; keep audio-engine state (AudioContext, nodes) out of React entirely and bridge with a command bus. Valtio's proxy model fights immer-style patches; not recommended here.
- Autosave: debounce 1–2 s after the last commit → `idb-keyval`/Dexie `put(projectId, {doc, version})`; audio files and peak pyramids → OPFS files (worker `createSyncAccessHandle` for peak writes); call `navigator.storage.persist()` on first project save and surface a "stored locally, may be evicted on iOS after 7 days without use" notice; account sync (the app already has API sync) remains the durable copy.
- Collaboration later: Yjs `Y.Map`/`Y.Array` mirror of the document with `trackedOrigins` so undo is local-only, `y-indexeddb` for offline, `y-websocket` server (openDAW ships a `server/yjs-server` package in its monorepo — [openDAW packages tree](https://github.com/andremichelle/openDAW/tree/main/packages)).

### Gaps
- No published pattern for marrying immer patch history with Yjs documents; teams pick one.
- Dexie's local Blob handling in IndexedDB (as opposed to Cloud offloading) was not read from its docs.

## Key question 8 — Visual design of pro DAW dark themes: documented palettes/tokens (Logic, Live 12, Bitwig, FL Studio, Reaper, web DAWs), typography, hairlines, region colours, contrast; WCAG 2.2 AA in a dense dark UI

### Takeaway
No vendor publishes design tokens for Logic Pro 11, Live 12, Bitwig or FL Studio; the only documented theming systems are REAPER's WALTER/`rtconfig.txt` and Ableton's community-reverse-engineered `.ask` XML (hex colours since Live 11). Build the studio theme as Tailwind v4 `@theme` CSS variables (OKLCH), and meet WCAG 2.2 AA with 4.5:1 text, 3:1 control boundaries/focus indicators (1.4.11), 24 × 24 CSS px targets (2.5.8), unobscured focus (2.4.11) and a `prefers-reduced-motion` path.

- Tailwind v4 (2025-01-22): `@theme { --color-…: oklch(…) }` emits every token as a native CSS custom property on `:root`; spacing derives from `--spacing: 0.25rem`; default palette moved to OKLCH; opacity modifiers compile to `color-mix(in oklab, …)`; container queries in core (`@container`, `@sm:`, `@max-*`); `starting:` variant for `@starting-style` — [Tailwind v4 blog](https://tailwindcss.com/blog/tailwindcss-v4); 4.3.5 current — [npm registry](https://registry.npmjs.org/tailwindcss)

- Dark-mode guidance (generic): use a range of dark greys rather than `#000000` — [Muzli dark-mode guide](https://muz.li/blog/dark-mode-design-systems-a-complete-guide-to-patterns-tokens-and-hierarchy/); GitLab provides dark values under the same token names in `.dark` files — [GitLab design tokens](https://docs.GitLab.com/ee/development/fe_guide/design_tokens.html)

### Inferences
- Token set for the studio (Tailwind v4 `@theme`): `--color-bg-base` (#0C0B14 per the project's existing token), `--color-bg-raised` (+4–6 % L in OKLCH for panes), `--color-bg-lane` / `--color-bg-lane-alt` (alternating track rows), `--color-hairline` at ≥ 3:1 against the pane only where it is the sole boundary of a control (1.4.11), `--color-accent` (#C89B5F), a 16-colour region palette with on-region text chosen to hit 4.5:1 (region colour sets in Logic/Live are unverified here, so pick OKLCH hues at constant L/C), `--color-focus` ring 2 px solid at ≥ 3:1 against both the control and the background. Hairline 1 px borders can stay low-contrast when they are decorative dividers (not a control boundary).
- Density vs WCAG: Logic-style 18 px knobs and 20 px track buttons fail 2.5.8 unless padded to a 24 px hit area or spaced so 24 px circles do not intersect; 2.4.11 means the sticky transport bar and bottom drawer must use `scroll-padding` so a focused region/strip is never fully covered.
- Reduced motion: gate playhead smoothing, meter decay animations and panel slide transitions behind `@media (prefers-reduced-motion: reduce)` (SCR40), keeping the playhead moving (essential) but dropping non-essential easing.

- No source was found measuring contrast ratios of shipping DAW UIs.

## Key question 9 — Mobile/tablet adaptation: what web DAWs do at 390 px, touch targets, bottom sheets, single-pane navigation, Logic Pro for iPad patterns, iOS Safari gotchas

### Takeaway
At phone widths collapse the five-pane layout to one pane at a time (track list → arrange → editor as a bottom sheet) with a persistent transport; Logic Pro for iPad's precedent is tile-based plug-ins, a Details view that fills the width, and a view control bar that toggles Browser/Inspector/Fader/Plug-ins/Mixer/Editors. On iOS Safari use `dvh`/`svh` not `100vh`, `env(safe-area-inset-*)` with `viewport-fit=cover`, `touch-action: manipulation` to kill double-tap zoom, 16 px inputs to prevent auto-zoom, and create/resume the `AudioContext` inside a tap handler.

### Cited Findings
- Logic Pro for iPad: control bar and view control bar; areas: Tracks area, Live Loops, Browser, Inspector, Fader, Plug-ins area (Track/Sends/Output views + Details view), Mixer, Editors (Audio, Piano Roll, Session Player, Step Sequencer), Play Surfaces — [Apple guide TOC](https://support.apple.com/guide/logicpro-ipad/toc); plug-ins appear as tiles with key parameters editable in place; Details view "expands to fill the width of the Logic Pro window" with mini tiles at the bottom for switching (only when opened from the Plug-ins area, not the Mixer); control-size option and a resize handle to toggle max/previous size — [Apple guide, Details view](https://support.apple.com/guide/logicpro-ipad/lpipc723a5bc/ipados), [Apple guide, plug-in tiles](https://support.apple.com/guide/logicpro-ipad/lpip10a08756/ipados)
- BandLab: the browser Mix Editor is the flagship (multi-track timeline, piano roll, effect chains, mixer, loop library) with the transport top-centre; the mobile app has "a smaller editing area and fewer precision tools than the browser version" (secondary source) — [Audeobox BandLab mobile vs desktop](https://www.audeobox.com/learn/bandlab/bandlab-mobile-vs-desktop/); Soundtrap's layout is described as minimal with most tools in menus (weak secondary source) — [tomatotasty post](https://tomatotasty.pages.dev/posts/7-free-online-daws-for-music-production-and-podcasting)
- Viewport units: `vh` ignores dynamic toolbars so `100vh` elements "bleed out of the viewport" on load; `svh` = toolbars expanded, `lvh` = retracted, `dvh` moves between them but is throttled and may skip updates during some gestures; support Chrome/Edge 108, Firefox 101, Safari 15.4 — [web.dev viewport units](https://web.dev/blog/viewport-units); declare `height: 100vh` before `100dvh` as fallback and add `viewport-fit=cover` + `env(safe-area-inset-bottom)` for fixed bottom bars; iOS Safari auto-zooms inputs under 16 px; `touchcancel` fires when Safari takes a system gesture (secondary) — [OpenReplay mobile issues](https://blog.openreplay.com/pt/5-mobile-web-problemas-solucoes/), [iOS Safari gotchas guide](https://abratabia.com/mobile-web-games/ios-safari-gotchas.php)
- `touch-action: manipulation` disables double-tap-to-zoom and so removes the click delay; `none` lets the app own all gestures; the browser sends `pointercancel` when it takes a gesture — [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action)
- Audio unlock: an `AudioContext` created outside a user gesture starts `suspended`; create it in a `click` handler or check `state === "suspended"` and call `resume()` in the handler — [MDN Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices); Chrome logs a console error when a context is not resumed after a gesture (secondary) — [Matt Montag](https://www.mattmontag.com/web/unlock-web-audio-in-safari-for-ios-and-macos)
- Safari storage: script-created storage is deleted after 7 days without interaction; Safari browser apps get ~60 % of disk, embedded WebViews ~15 % — [MDN storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
- Target size ≥ 24 × 24 CSS px (AA) — [W3C 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html); touch-based AT may not send slider key events, so test sliders on touch devices — [APG slider](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)
- Tailwind v4 container queries (`@container`, `@sm:`…) are in core — [Tailwind v4 blog](https://tailwindcss.com/blog/tailwindcss-v4); dockview advertises touch/mobile support — [dockview GitHub](https://github.com/dockview/dockview)

### Inferences
- At ≤ 640 px: single-pane stack driven by container queries on the studio root (not viewport queries, so the same code works when the studio is embedded or in iPad Split View); top transport stays `position: sticky` with `padding-bottom: env(safe-area-inset-bottom)` on a bottom tab bar (Tracks | Arrange | Editor | Mixer); the editors drawer becomes a bottom sheet (`<dialog>` or Radix Dialog with `touch-action: pan-y` on its body); inspector becomes a sheet opened from the selected region/track. Track header width 96 px, region handles ≥ 24 px, long-press (500 ms) for context menus since right-click is absent.
- Logic-for-iPad patterns to borrow: parameter "tiles" for the inspector (6–8 key controls per plug-in with a Details view), a view control bar of toggles instead of resizable split panes on touch, and a control-size setting.
- iOS Safari checklist: root `height: 100dvh` with `100vh` fallback; `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`; `touch-action: manipulation` globally and `none` on canvases; inputs ≥ 16 px; single `AudioContext` created/resumed in the first tap; treat `pointercancel`/`touchcancel` as pointer-up to end drags cleanly; expect OPFS/IndexedDB eviction after 7 idle days and nudge sign-in sync.

### Gaps
- No primary documentation of BandLab's or Soundtrap's mobile-browser layouts at 390 px was found (both are JS apps; search quota ran out before trying their help centres).
- The Logic Pro for iPad "Logic Pro interface" page body did not load (only the TOC), so pane placement and mutual-exclusion rules are unverified.
