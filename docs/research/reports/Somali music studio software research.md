# Six weeks to a Logic-class Somali studio

The studio QaraamiGen already has is the right architecture; the gap to "Logic-Pro-like" is not a new engine but four finishing layers, and the six weeks before the 2026-12-23 deadline should be spent on them in this order: a measured per-device latency calibration (browser round trips are **40–65 ms by default and ~100 ms in Safari**, and every commercial browser DAW that compensates from estimates misaligns recordings by 10–190 ms), an evidence-based Learn loop built on the one strong pedagogy result (visual pitch feedback **with an explicit right/wrong verdict** retains at transfer; contour-only mirrors do not), the handful of Logic grammar details that reviewers actually use to separate "pro" from "toy" (stacked ruler zones, an editable LCD, a per-track inspector strip, a searchable key-command registry, named revisions), and a transactional project model with patch-based undo backing OPFS persistence. The only controlled benchmark of browser DSP found (WAC 2022) shows plain-JavaScript AudioWorklets competitive with WebAssembly, so the Karplus–Strong oud and frame-drum durbaan should stay in JS, consolidated into one engine worklet, with WASM reserved for porting existing code. The Somali musicology sources are strong enough to ground a glossary of genres and instruments but carry three live disputes (dhaanto's origin and metre, balwo's date, the first kaban's identity) that the 72-term dictionary must mark as contested rather than resolve. The companion Hugging Face dataset is a documentation-and-licensing problem rather than a data problem: an audiofolder plus Parquet layout, a Datasheets-shaped card whose core is an honest "Excluded material" section, per-subset licences (CC BY 4.0 for the project's own work, CC BY-NC 4.0 for MusicGen-adapter output, with the card stating that purely machine-generated audio may not be copyrightable at all), entity-level splits, `mir_eval` defaults, and a DOI minted only after the repository is public.

## Keep the JavaScript engine, consolidate it, and measure latency instead of estimating it

The engine decision is already made, and the research confirms it. The Web Audio render quantum is 128 frames, which at 48 kHz gives every node and every `process()` call about **2.67 ms** per block on a dedicated real-time thread; the Firefox team's guidance is to avoid allocation and promises in that path, reuse typed arrays, and transfer `ArrayBuffer`s rather than copy them ([Mozilla Hacks](https://hacks.mozilla.org/2020/05/high-performance-web-audio-with-audioworklet-in-firefox/)). The only controlled JS-versus-WASM AudioWorklet benchmark found, Roma's WAC 2022 study of polyBLEP sawtooth, sine and biquad worklets on an M1 Pro, concluded that "the pure JS version stands well against WebAssembly implementations", that per-sample WASM calls are the slow path because of call overhead, and that "WebAssembly is clearly not a magic bullet that makes code automatically faster"; its real advantage is the absence of a garbage collector ([Zenodo 6767468](https://zenodo.org/records/6767468)). Jack Schaedler's Karplus–Strong stress tester reached the same place from the other side: JS strings are "surprisingly fast in modern browsers" after JIT warm-up, `MessagePort` allocates and triggers GC, and the recommendation is to simulate many strings inside one worklet node rather than one node per string ([karplus-stress-tester](https://github.com/jackschaedler/karplus-stress-tester)). The concrete next step for the existing oud and durbaan is therefore consolidation, not rewriting: one engine worklet that owns every voice, a pre-allocated voice pool, and the "zero allocations per render quantum" discipline openDAW documents for its `BlockRenderer` ([openDAW performance notes](https://raw.githubusercontent.com/andremichelle/opendaw/main/docs/performance.md)). Every serious browser DAW that documents its engine has converged on exactly this shape: a single engine in an AudioWorklet (openDAW's Rust→WASM `engine.wasm` exposed as one processor, Signal's single-worklet wavelet synth), workers for analysis and file I/O, and a transactional project model mirrored to the audio thread so that "the audio thread never reads main thread state directly" ([openDAW introduction](https://raw.githubusercontent.com/andremichelle/opendaw/main/introduction.md); [Signal ARCHITECTURE.md](https://github.com/ryohey/signal/blob/main/ARCHITECTURE.md)).

Timing should follow the look-ahead scheduler pattern with the timer in a Web Worker. Chris Wilson's canonical design queues events up to 100 ms ahead on `AudioContext.currentTime` from a 25 ms JS timer, which survives a 50 ms main-thread stall, at the cost that a tempo change only takes effect after already-queued notes ([web.dev](https://web.dev/articles/audio-scheduling)). Tone.js ships the production defaults: `clockSource: "worker"`, `lookAhead: 0.1`, `updateInterval: 0.05`, with the explicit note that look-ahead plus update interval is the total scheduling latency ([Tone.js Context.ts](https://raw.githubusercontent.com/Tonejs/Tone.js/dev/Tone/core/context/Context.ts)). The worker matters because Chrome 88 throttles main-thread timer chains in hidden pages to once per minute after five minutes unless the page has been audible in the last 30 s, and "a silent audio track doesn't count" ([Chrome Developers](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)). For tempo maps that change mid-tick, Strudel's checkpoint-based cycle-to-seconds mapping, which resets the checkpoint and re-queries the remainder of the tick on a tempo change rather than accumulating drift, is the cleanest reference ([strudel cyclist.mjs](https://codeberg.org/uzu/strudel/raw/branch/main/packages/core/cyclist.mjs)). Count-in and loop regions belong in the engine-side transport, as openDAW keeps them in a Rust `transport` crate that "handles playback position, tempo map, and loop handling" ([openDAW introduction](https://raw.githubusercontent.com/andremichelle/opendaw/main/introduction.md)); no browser DAW publishes a count-in implementation write-up, so this is a design rule rather than a measured precedent. Bounce goes through `OfflineAudioContext`, which renders "as fast as it can" and has been Baseline since April 2021 ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext)).

Recording is where the current studio is most exposed, and the fix is a one-click calibration. Jeff Kaufman measured a 2016 MacBook at **Chrome ≈67 ms and Firefox ≈55 ms round trip with defaults**, falling to **19 ms and 14 ms** only with `latencyHint: 0` and `echoCancellation`, `noiseSuppression` and `autoGainControl` all off, and found that no browser API reports end-to-end latency accurately, so "measure it" ([jefftk.com](https://www.jefftk.com/p/browser-audio-latency)). The WAC 2025 maximum-length-sequence tool, over 100 runs per browser, put a 2021 MacBook Pro at **Chrome 52.3 ms, Firefox 38.9 ms and Safari 100.0 ms**, with Firefox at zero jitter everywhere and Chromium at ~8 ms standard deviation on Ubuntu; the same study then recorded into online DAWs after their own compensation and found Soundtrap placing takes **~180–194 ms early**, BandLab anywhere from −74 ms to +0.7 ms depending on the machine, Amped −8 to −11 ms, and an MLS-calibrated reference within **~1 ms** ([gilpanal/weblatencytest](https://github.com/gilpanal/weblatencytest)). Soundtrap's answer is a "Latency Calibration" run from the microphone track plus a "Low latency mode" toggle ([Soundtrap support](https://support.soundtrap.com/hc/en-us/articles/25549534050962-Latency-Calibration)). The Record mode should therefore play a click or MLS through the speakers, record it, cross-correlate, store the offset per input/output device pair, shift every take by that amount, and re-measure when the device list or `outputLatency` changes; input monitoring through the browser adds the full round trip, so direct hardware monitoring is the default and browser monitoring an opt-in that displays the measured figure. `AudioContext.outputLatency` only reached Baseline in March 2025 and `latencyHint` is unsupported in Firefox ([mdn/browser-compat-data](https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/AudioContext.json)), which is another reason not to trust estimates.

iOS Safari needs its own checklist. Web Audio used the ringer channel, so the silent switch muted it until iOS 17 added `navigator.audioSession.type = "playback"`, which WebKit now points to as the fix ([WebKit bug 237322](https://bugs.webkit.org/show_bug.cgi?id=237322); [MDN AudioSession](https://developer.mozilla.org/en-US/docs/Web/API/AudioSession)); the site already applies this fix site-wide on master, so the studio inherits it. Three open WebKit bugs still bite a recorder: on iOS 26.2–27 any output "crackles while getUserMedia mic capture with echo cancellation is active", and turning EC off routes output to the earpiece at low volume ([WebKit bug 326286](https://bugs.webkit.org/show_bug.cgi?id=326286)); switching to a Bluetooth route changes the output sample rate and distorts Web Audio ([WebKit bug 258864](https://bugs.webkit.org/show_bug.cgi?id=258864)); and a home-screen PWA can come back from the background with a context that reports `running` but is silent ([WebKit bug 291892](https://bugs.webkit.org/show_bug.cgi?id=291892)). The design consequences are one long-lived `AudioContext` created and resumed in the first tap, a `visibilitychange` handler that re-checks state and re-resumes on the next gesture, treating `context.sampleRate` as mutable across sessions, and an explicit on-device EC choice for iOS recorders. Superpowered's unverified but widely repeated figure of a **~350 MB** memory ceiling before an iPhone Safari tab dies ([superpowered.com](https://superpowered.com/riding-the-latest-waves-on-the-web)) and the computed cost of decoded audio, roughly 23 MB per stereo minute at 48 kHz float, together argue for streaming audio from the Origin Private File System rather than holding whole sessions decoded.

Persistence should move audio blobs from IndexedDB to OPFS and keep IndexedDB for project metadata. OPFS's `FileSystemSyncAccessHandle` gives synchronous reads and writes inside a Worker and is "the entry point to the fastest possible file operations" ([web.dev](https://web.dev/articles/origin-private-file-system)); openDAW stores files there through a worker, bundles projects with jszip and encodes WAV itself ([openDAW introduction](https://raw.githubusercontent.com/andremichelle/opendaw/main/introduction.md)). Both stores share one per-origin quota, and Safari's rule that script-created data is deleted after seven days without user interaction means a musician who records on an iPhone and returns a fortnight later may have lost unsynced audio ([MDN storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)); the studio should call `navigator.storage.persist()` on first save, show a "stored locally" notice, and push to R2 through the platform's existing presigned-URL path early. Exports are cheap: WAV by hand, MP3 through the LAME WASM build in `wasm-media-encoders` at about 66 KiB gzipped ([npm](https://www.npmjs.com/package/wasm-media-encoders)), FLAC through mediabunny's libFLAC build because "No browser currently supports FLAC encoding in their WebCodecs implementations" ([mediabunny](https://mediabunny.dev/guide/extensions/flac-encoder)), Opus through WebCodecs `AudioEncoder` where `isConfigSupported` passes (Chrome 94, Firefox 130, Safari 26 per [mdn/browser-compat-data](https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/AudioEncoder.json)), and loudness normalisation to the project's existing −16 LUFS target through the BS.1770 `loudness-worklet` on an offline pass ([loudness-worklet](https://socket.dev/npm/package/loudness-worklet)). MIDI goes through `@tonejs/midi` ([Tonejs/Midi](https://github.com/Tonejs/Midi)) and notation through the Verovio toolkit the transcriber already ships ([rism-digital/verovio](https://github.com/rism-digital/verovio)); DAWproject, the ZIP-plus-XML interchange format Bitwig, Studio One and Cubase adopted and openDAW implements in TypeScript, is the only route to desktop users and can wait ([bitwig/dawproject](https://github.com/bitwig/dawproject)).

Analysis belongs in Workers, never in the audio thread. essentia.js, the Essentia C++ library compiled to a ~2.5–3 MB WASM module, ran most features on a 30 s clip at **1.5–6.8 % of audio duration** on desktop browsers, with pYIN the outlier at 54.7 % and Chrome on Android the slowest platform; its TensorFlow.js models took 3.7–28 s end to end and VGGish failed outright on iOS and Chrome/Android ([TISMIR](https://transactions.ismir.net/articles/10.5334/tismir.111)). For the fretless oud tuner, McLeod (pitchy) or YIN (pitchfinder) at 1024–2048-sample frames is enough and sub-10 ms; pitchfinder's maintainers warn that YIN "occasionally provides values that are wildly incorrect" and that McLeod "has been reported to perform better on lower frequencies" ([pitchfinder](https://github.com/peterkhayes/pitchfinder); [pitchy](https://github.com/ianprime0509/pitchy)), so the existing browser YIN analyser should gain a clarity gate and an octave-slip check if it does not already have one. CREPE and Basic Pitch stay offline in a Worker. SharedArrayBuffer ring buffers such as ringbuf.js are the standard wait-free queue but require `Cross-Origin-Embedder-Policy: require-corp` and `Cross-Origin-Opener-Policy: same-origin`, which block any cross-origin iframe or script lacking CORP headers ([padenot/ringbuf.js](https://github.com/padenot/ringbuf.js); [web.dev COOP/COEP](https://web.dev/articles/coop-coep)); on a Vercel site that loads Stripe, isolation is a site-wide decision with real breakage risk, so the studio should stay on `MessagePort` with transferred `ArrayBuffer`s and trial isolation only on the `/studio` route with Report-Only headers first.

For the instruments themselves the evidence is thin and must be labelled as such: no oud-specific physical-modelling paper or browser implementation was found, and no frame-drum model beyond Faust's `djembe`. What the sources do establish is the recipe. Jaffe and Smith's extended Karplus–Strong adds a pick-direction lowpass, a pick-position comb filter, a damping filter, a dynamic-level lowpass, a tuning allpass for fractional delay and a stiffness allpass ([CCRMA PASP](https://ccrma.stanford.edu/~jos/pasp/Extended_Karplus_Strong_Algorithm.html)); commuted synthesis folds the body's impulse response into the excitation table so the expensive body filter disappears ([CCRMA PASP](https://ccrma.stanford.edu/~jos/pasp/Commuted_Synthesis.html)); and Faust's `djembe` is a modal resonator bank with "empirically calculated" modes excited by a strike ([faustlibraries](https://faustlibraries.grame.fr/libs/physmodels/)). The inference for the kaban is two slightly detuned delay lines per course, continuous delay-length glides for fretless pitch, the comb for risha position and a measured or synthesised body IR applied by commutation; for the durbaan, six to twenty decaying sinusoids with hand damping modelled as faster decay. Plugin hosting through WAM 2.0 (40+ plugins, iOS Safari supported, SharedArrayBuffer ring buffers between worklets) or the October 2026 WebCLAP route openDAW now hosts is real but is a post-deadline feature ([WAM docs](https://www.webaudiomodules.com/docs/intro); [openDAW newsletter](https://buttondown.com/opendaw/archive/opendaw-now-runs-webclap-plugins/)).

What to avoid is as clear as what to adopt: no WASM rewrite of working JS DSP; no per-sample WASM calls; no one-worklet-per-voice topology; no second `AudioContext` (Chrome once threw at six per process and Chromium's advice was "one per app", which should be kept as a design rule even though no source confirms the cap still exists) ([W3C public-audio](https://lists.w3.org/Archives/Public/public-audio/2014JulSep/0137.html)); no ffmpeg.wasm in the client bundle at ~30 MB plus COOP/COEP for the threaded build; no site-wide cross-origin isolation before a Report-Only trial; no Ableton Link, which has no browser target ([Ableton/link](https://github.com/Ableton/link)); and no copying of openDAW code, which is AGPL-3.0 with a commercial dual licence, into an Apache-2.0 repository ([openDAW](https://github.com/andremichelle/opendaw)).

## Render like a whiteboard app, not like a form: canvas layers, one rAF loop, patch-based undo

The UI layer should follow the whiteboard and spreadsheet teams who have published numbers, because no web DAW has. RAIL budgets 10 ms of application work per 16 ms frame and 50 ms for input processing, with dragging, panning and pinch-zoom counted as animation ([web.dev RAIL](https://web.dev/articles/rail)); monday.com found that "it was not possible to reach 60fps while using DOM based cells" even when the cells were empty and that each cell must draw in under 0.05 ms, and solved it with a screen-sized canvas layered over the DOM, frame skipping when nothing changed and offscreen glyph caches ([monday.com engineering](https://engineering.monday.com/the-power-of-the-canvas-api-a-deep-dive-into-how-we-transformed-our-table-performance-at-monday-com-part-2)); tldraw culls a 10,000-shape page to ~50 rendered DOM shapes with a spatial index and, in v4.4, moved selection and hover indicators from SVG to a 2D canvas for "up to 25x faster rendering" with an R-tree for O(log n) brushing ([tldraw performance](https://tldraw.dev/sdk-features/performance); [tldraw v4.4.0](https://tldraw.dev/releases/v4.4.0)). Translated to the existing arrange view, the target is: track rows virtualised with `@tanstack/react-virtual` using `estimateSize` per track height and `scrollMargin` equal to the ruler height ([TanStack Virtualizer API](https://tanstack.com/virtual/latest/docs/api/virtualizer)); one DPR-scaled `<canvas>` per visible lane for waveforms and MIDI previews, redrawn only on a dirty flag; regions kept as absolutely positioned DOM elements so they stay focusable and keep the pointer-event drags already written; selection outlines, marquee and snap guides on one overlay canvas; and the playhead and meters driven by a single `requestAnimationFrame` loop that writes `style.transform` and canvas pixels from `AudioContext.currentTime`, never through React state. The idle-CPU study of canvas apps is the warning here: Excalidraw's ~1.2 % idle cost came from hover and pointer position living in React state, and tldraw's tick manager runs every frame without a dirty flag ([dev.to](https://dev.to/eugenioenko/why-your-drawing-app-uses-2-cpu-when-youre-not-using-it-10e0)); Zustand's transient `subscribe`-into-a-ref pattern is the documented escape ([Zustand README](https://github.com/pmndrs/zustand)). Canvas memory scales with width × height × DPR², so a 256 px waveform on a 2× display costs four times the memory and canvases wider than the viewport must never be allocated ([wavesurfer performance](https://wavesurfer.xyz/docs/performance/)).

Waveforms need a peak pyramid, not a wavesurfer instance per clip. wavesurfer's own docs say decoding "allocates the entire file as raw PCM in memory", that a 60-minute stereo track can exceed 500 MB, that its regions are DOM elements which glitch in the thousands, and that "for very dense data, consider a custom canvas overlay" ([wavesurfer performance](https://wavesurfer.xyz/docs/performance/)). The pattern to build is a 1-D mipmap: min/max pairs at 1, 2, 4 … 2^k samples per bucket, each level derived from the previous, interpolating between the two nearest levels at draw time ([Stack Overflow](https://stackoverflow.com/a/71423858)), computed once per file in a Worker (`comlink` for the RPC), stored as 8-bit pairs in OPFS keyed by file hash, with only the two levels nearest the current zoom in memory. wavesurfer 8 (BSD-3) or peaks.js 4 (LGPL-3, which needs a licence check against the Apache-2.0 repo) are fine for the single-file audio editor drawer only ([wavesurfer releases](https://github.com/katspaugh/wavesurfer.js/releases); [npm peaks.js](https://registry.npmjs.org/peaks.js)).

The pane shell should stay on `react-resizable-panels` v4 — pixel sizing, `role="separator"` keyboard resizing, `defaultLayout`/`onLayoutChanged` persistence, a React 19 peer and weekly releases (4.19.1 on 2026-11-06) ([GitHub](https://github.com/bvaughn/react-resizable-panels); [npm](https://registry.npmjs.org/react-resizable-panels)) — and reach for `dockview-react` only if panes must tear off into tabs or popout windows, since dockview documents no keyboard model ([dockview](https://github.com/dockview/dockview)). `golden-layout` has had no release since September 2022 ([npm](https://registry.npmjs.org/golden-layout)), and the npm piano-roll and keyboard packages (`webaudio-pianoroll` 0.6.0 from 2019, `react-piano` 3.1.3 from 2019) are reference code, not dependencies ([npm react-piano](https://registry.npmjs.org/react-piano); [webaudio-pianoroll](https://github.com/g200kg/webaudio-pianoroll)). "Screensets" cost almost nothing: Logic stores display size, zoom, window positions and which panes are open as numbered presets recalled by digit keys and auto-saved on switch ([Apple Logic Pro guide](https://support.apple.com/guide/logicpro/create-recall-and-switch-screensets-lgcp9bbbcb23/mac)); a JSON preset of pane sizes, zoom and visible editors per project bound to 1–9 reproduces it. Because the README warns of hydration layout shift with percentage defaults and the studio needs `AudioContext` anyway, the shell should render as a `'use client'` component loaded through `next/dynamic` with `ssr: false`, which the Next.js guide confirms works only inside Client Components ([Next.js lazy loading](https://nextjs.org/docs/app/guides/lazy-loading)).

State and undo should be rebuilt around immer patches. `produceWithPatches` returns the next state plus forward and inverse patches in an RFC 6902-like format, and `applyPatches` replays them onto another base ([Immer patches](https://immerjs.github.io/immer/patches/)); the history entry is `{patches, inversePatches, label, ts}`, and a drag gesture opens a pending entry on `pointerdown`, accumulates patches on `pointermove` and commits on `pointerup`, which gives deterministic one-step-per-drag undo where Yjs relies on a 500 ms `captureTimeout` and zundo on a throttle ([Yjs UndoManager](https://docs.yjs.dev/api/undo-manager); [zundo](https://github.com/charkour/zundo)). zundo's full-snapshot default is wasteful for a 10k-note project; the patch log is small enough to double as the autosave op-log for crash recovery. Signal's lesson is the one to take about React: its domain state lives outside React behind `useSyncExternalStore`, every mutation is a transaction with a single notification, and MobX was abandoned because it "leaked mutable state into app" ([Signal ARCHITECTURE.md](https://github.com/ryohey/signal/blob/main/ARCHITECTURE.md)). Collaboration, if it ever comes, is Yjs: 39 ms parse and 3.2 MB on the B4 real-world trace against Automerge 2's 1,805 ms, with Automerge 3 having since cut memory tenfold ([crdt-benchmarks](https://github.com/dmonad/crdt-benchmarks); [Automerge 3](https://automerge.org/blog/automerge-3/)); it is out of scope for six weeks.

Controls and keyboard handling have standards to follow rather than libraries to adopt. Knobs and faders are WAI-ARIA sliders with `aria-valuenow/min/max/text`, `aria-orientation="vertical"` for faders, arrows ±1 step, Home/End and Page Up/Down for coarse steps ([WAI-ARIA APG](https://www.w3.org/WAI/ARIA/apg/patterns/slider/)); the only maintained React knob primitive, `react-knob-headless` 0.4.0, stops its peer range at React 18 and ships no keyboard handler ([npm](https://registry.npmjs.org/react-knob-headless)), so a 60-line `role="slider"` div with pointer capture, Shift for fine mode and double-click reset is the better investment. The LCD needs `font-variant-numeric: tabular-nums` so changing digits do not shift layout ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/font-variant-numeric)). Shortcuts should bind letters and digits by `KeyboardEvent.code`, which names the physical key independent of layout, and symbols by `key` ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code)); `tinykeys` 4.0.1 accepts both forms, ignores inputs by default and weighs about a kilobyte ([tinykeys](https://github.com/jamiebuilds/tinykeys)), `cmdk` gives an accessible command palette with built-in filtering up to a few thousand items ([cmdk](https://github.com/pacocoursey/cmdk)), and Radix Menubar and ContextMenu bring roving tabindex and typeahead for free ([Radix](https://www.radix-ui.com/primitives/docs/components/menubar)). One registry of `id → {binding, label, scope, handler}` should feed the hotkey layer, the palette and an in-app overlay so every command is discoverable. Musical typing (Logic's A W S E D F T G Y H U J map with Z/X octave) must live in its own scope, enabled only when a MIDI track is armed, focus is inside the arrange or piano roll, no editable element is active and no menu is open, because it collides with single-letter tool shortcuts and digit-key screenset recall ([Apple Logic Pro guide](https://support.apple.com/guide/logicpro/use-musical-typing-lgcp3bcb92d1/mac)).

Accessibility and theming have hard numbers. WCAG 2.2 AA requires 3:1 contrast for control boundaries, states and focus indicators ("2.999:1 fails") ([W3C 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)), 24 × 24 CSS px targets with a spacing exception ([W3C 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)), and that a focused element is never entirely hidden by sticky bars, which means the transport bar and bottom drawer need `scroll-padding` ([W3C 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)). No vendor publishes design tokens for Logic, Live, Bitwig or FL Studio; Tailwind v4's `@theme` emits every token as a CSS custom property in OKLCH ([Tailwind v4](https://tailwindcss.com/blog/tailwindcss-v4)), so the studio's token set should start from the project's `#0C0B14` base and `#C89B5F` accent, raise pane backgrounds by 4–6 % lightness, and pick a 16-colour region palette at constant lightness and chroma with on-region text at 4.5:1. On phones, the five panes collapse to one at a time with a sticky transport; `100dvh` with a `100vh` fallback, `viewport-fit=cover` with safe-area insets, `touch-action: manipulation` globally and `none` on canvases, 16 px inputs to stop auto-zoom and `pointercancel` treated as pointer-up are the iOS Safari rules ([web.dev viewport units](https://web.dev/blog/viewport-units); [MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action)). Testing uses `standardized-audio-context-mock` 10.0.1 for the engine (`web-audio-test-api` has been dead since 2015) ([GitHub](https://github.com/chrisguttandin/standardized-audio-context-mock); [npm](https://registry.npmjs.org/web-audio-test-api)), Playwright `toHaveScreenshot` with `maxDiffPixelRatio` around 0.01 for canvas layers and an app-side `freezeAnimations()` hook because Playwright's animation disabling does not stop JS-driven canvas loops ([Playwright](https://playwright.dev/docs/api/class-pageassertions#page-assertions-to-have-screenshot-1); [Argos](https://argos-ci.com/blog/fix-flaky-visual-tests)), and a CI budget of INP ≤ 200 ms at p75 and p95 frame time ≤ 16 ms on an "open 100-track project, drag, zoom" trace ([web.dev INP](https://web.dev/articles/inp)).

## Logic's grammar is ten details, and the studio shell already has half of them

"Logic-Pro-like" in November 2026 means Logic Pro 13's model, released 5 November with a unified Browser replacing Library and Loop Browser, a consolidated inspector, an in-window Play Surface and an intelligent assistant gated to Apple silicon and a Creator Studio subscription ([Apple, What's new in Logic Pro 13](https://support.apple.com/guide/logicpro/whats-new-in-logic-pro-13-lgcp4a62a494/mac); [Apple support 125029](https://support.apple.com/125029)). Stripped of the ML, the layout grammar is a fixed set. The control bar is the window's navigation: a toggle for every pane, transport and an LCD in the centre with five modes (Beats & Project, Beats & Time, Beats, Time, Custom) that doubles as the editor for tempo, key and time signature by dragging digits or double-clicking ([Apple](https://support.apple.com/guide/logicpro/change-the-display-mode-in-logic-pro-for-mac-lgcp127f51bc/mac); [Apple](https://support.apple.com/guide/logicpro/customize-the-control-bar-lgcp5bdd6d9d/mac)). The ruler is three stacked hit zones: the upper zone sets the yellow cycle strip, the middle third carries the red autopunch stripe, and the lower zone moves the playhead ([Apple, cycle](https://support.apple.com/guide/logicpro/use-the-cycle-area-lgcp59e41e86/mac); [Apple, autopunch](https://support.apple.com/guide/logicpro/punch-in-and-out-of-audio-recordings-lgcpb19bfd0d/mac)). Global tracks sit below the ruler with Arrangement, Marker, Signature and Tempo visible by default and the Chord track optional ([Apple](https://support.apple.com/guide/logicpro/global-tracks-overview-lgcp4994bead/mac)). Regions are rounded rectangles coloured by type — audio blue, MIDI green, Session Player yellow, pattern violet — with loop notches when dragged from the upper-right edge ([Apple, loops](https://support.apple.com/guide/logicpro/loops-and-one-shots-overview-lgcpa039bc05/mac); [Apple, regions](https://support.apple.com/guide/logicpro/regions-overview-lgcpf7c0d0bb/mac)). Reproducing those zones and colours is what makes a timeline "feel like Logic" before any feature parity, and Apple publishes none of the pixel metrics, so widths, heights and radii must be measured from screenshots.

The two panes that make a sound browser feel integrated rather than bolted on are Link to Selection, where "the Browser view follows the track selection", and Replace Mode, where picking a patch replaces the current one on the selected track; the 13.0 Browser adds tag chips, an All Filters sheet with paired tags such as Cold/Warm, list, attribute-table and Finder-column result layouts, per-row preview, and natural-language "sounds like" search that requires Apple silicon ([Apple, Browser](https://support.apple.com/guide/logicpro/browser-interface-lgcpe9cc40af/mac); [Apple, search](https://support.apple.com/guide/logicpro/search-for-sounds-in-the-browser-lgcp2f2c0c15/mac)). The inspector in Logic always shows two things: the selection's parameters (a Region inspector whose transposition and quantisation are non-destructive) and the selected track's full channel strip beside its output strip ([Apple](https://support.apple.com/guide/logicpro/inspector-interface-lgcpe9cc3b1d/mac)); the channel-strip component list — Setting, EQ display, input/instrument slot, effect slots, sends with level knobs, output, group, automation mode, pan, peak display with orange for over-0 dB-without-clipping, fader, meter, record, monitor, mute, solo, name — is a complete spec for a browser mixer strip, and the "Controls view" that renders every plug-in parameter as a labelled horizontal slider is both Apple's accessibility fallback and a free generic plug-in UI ([Apple](https://support.apple.com/guide/logicpro/channel-strip-controls-lgcpbc219210/mac)). Reviewers of browser DAWs police exactly this: the 2022 hands-on found that neither Soundtrap nor Soundation "has a dedicated mixer window" and called it the "most notable gap" ([DJ TechTools](https://djtechtools.com/2022/12/28/we-tested-3-online-music-creation-tools-you-can-try-in-2023-soundful-soundtrap-soundation)).

One bottom slot chosen by selection is the editor pattern: double-clicking a region opens the matching editor below the Tracks area, each with its own menu bar, local inspector and ruler, and pop-out windows are the escape hatch ([Apple, Piano Roll](https://support.apple.com/guide/logicpro/piano-roll-editor-interface-lgcpc788b136/mac)). The Step Sequencer's row headers (icon, mute/solo, row assignment, rotate, increment/decrement), its pattern-length support for 3/4, 4/4, 5/4 and 7/8, and its 12.0 ability to assign rows "to chord degrees rather than to fixed pitches" are the model for the durbaan pad sequencer ([Apple](https://support.apple.com/guide/logicpro/step-sequencer-overview-lgcp39acefc9/mac)). The Score editor exports and imports MusicXML, which the transcriber already produces ([Apple](https://support.apple.com/guide/logicpro/export-a-score-as-music-xml-lgcpbd38ba48/mac)). Logic keeps 200 undo steps and an Undo History window ([Apple](https://support.apple.com/guide/logicpro/undo-and-redo-edits-lgcp1dbd67ab/mac)), and its Key Commands window is searchable, filterable by Used, Unused and Conflicts, importable and exportable to a spreadsheet, with the most-used defaults a compact memorable set — B Browser, I Inspector, X Mixer, E Editors, P Piano Roll, N Score, C cycle, K click, Shift-K count-in, R record, Space play, L loop, Q quantise, Z zoom to fit ([Apple, key commands](https://support.apple.com/guide/logicpro/key-commands-overview-lgcp32e85cd9/mac); [Apple, global commands](https://support.apple.com/guide/logicpro/global-commands-lgcp02bf31b6/mac)). Letters and arrows are safe in a browser; Command-number and Command-letter combinations collide with the browser and need a capture toggle, which is how Logic's own Play Surface handles key commands with Esc and "Send Next Key".

Two Logic ideas are worth more to a Somali studio than any effect. ## Teach by ear with a verdict: the one strong result and the thresholds it implies

Across Yousician, Simply Piano, Flowkey, Melodics, Soundslice, GarageBand and Duolingo Music there are only about eight recurring mechanics, and the minimal viable loop every successful product shares is notation with a playhead, per-note green/red colouring, a wait mode that halts until the right note sounds, slow-down with pitch preserved, section looping and a per-song progress graph. Flowkey ships exactly Wait Mode, Slow Motion at 50 % or 75 % and Loop ([Yamaha flowkey](https://au.yamaha.com/en/products/contents/pianos/flowkey/); [Pianist Magazine](https://pianistmagazine.com/blogs/learn-all-the-songs-that-you-love-with-flowkey)); Melodics documents "Step-by-step (Wait Mode): When a note reaches the playhead, the performance pauses until you play the correct note", a BPM slider "right down to a stop" and Auto BPM that raises tempo **10 BPM at a time** on clean passes ([Melodics practice mode](https://support.melodics.com/en/articles/6777027-practice-mode)); Yousician auto-adjusts speed up or down from how you play ([Yousician support](https://support.yousician.com/hc/en-us/articles/115005259945-The-best-way-to-practice-piano)). Tempo floors reveal the audience: 50–75 % for sheet-music learners, 25 % for players in Soundslice, 5 % in Transcribe! and Anytune for by-ear transcription ([Transcribe!](https://www.seventhstring.com/xscribe/overview.html); [Anytune](https://apps.apple.com/us/app/id415365180)). An oral-tradition "learn by ear" mode should therefore go to at least 25 % and expose a one-tap half-speed button, and Soundslice's lesson that audio loops can be "perfectly timed" while video loops gap is the reason the Learn panel should loop decoded audio buffers, not media elements ([Soundslice blog](https://www.soundslice.com/blog/199/introducing-enhanced-slowdown-and-perfect-looping/)). Chrome Music Lab's Song Maker, which "restricts which notes are available based on the scale chosen, so most results sound consistent regardless of skill" ([Alphr](https://www.alphr.com/google/1008703/google-song-maker-chrome-musicians/)), is the simplest pentatonic-first design: at level one the kaban surface shows only the five degrees and it is impossible to be wrong.

The research literature justifies one design decision firmly and cautions against two. Blanco, Tassani and Ramirez randomised 47 beginners on violin and voice: the group given real-time visual pitch feedback plus knowledge of results (target as a bar, played pitch as a line) reached **14.7 cents absolute error on violin and 20.5 on voice** while aided, against 169 and 145 cents for a matched-timbre auditory group, and — the finding that matters — retained an **81-cent (violin) and 105-cent (voice) improvement at transfer** with the display removed, while the auditory group improved only during acquisition ([Blanco et al. 2021](https://www.frontiersin.org/articles/10.3389/fpsyg.2021.684693/full)). Welch's schema account, summarised there, holds that singing skill "require[s] external right/wrong feedback" early and that visual feedback without knowledge of results did not improve pitch matching; Wilson's thesis found marked improvement with real-time feedback but also that "cognitive load related to the decoding of visual information was a factor" ([Wilson 2007](https://ses.library.usyd.edu.au/handle/2123/1526)). The null results are real: Zaki-Azat found "no effect of real-time visual feedback training" on vocal control ([WLU thesis](https://scholars.wlu.ca/etd/1812)) and White's 2025 sight-singing study found computerised feedback "no more effective than receiving no feedback" ([White 2025](https://acda.org/wp-content/uploads/2025/12/IJRCSVol13White.pdf)). The design that survives this evidence shows the target, the learner's pitch and an explicit verdict; keeps the display cheap to decode (one line against one bar during performance, spectrograms only in review); and builds the fade-out in with scheduled blind repetitions — play with the display hidden, then reveal — so that **feedback-off accuracy becomes the headline progress metric**. Contour-only "mirror" displays like Riyaz's Smart Tanpura are pleasant but, on this evidence, do not by themselves produce learning ([Riyaz](https://riyazapp.com/blog/a-mirror-youve-never-seen-before/)). Interleaving helps long-term retention but hurts in-session performance and learners dislike it, so new learners get blocked repetition and only returning learners interleave across songs ([Carter & Grahn 2016](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC4989027/)); spacing is justified for repertoire memory above a threshold gap ([Katz et al. 2021](https://link.springer.com/article/10.1186/s41235-021-00345-7)) but a review states that "no data appear to exist" for a spacing effect on music motor skill ([PMC review](https://pmc.ncbi.nlm.nih.gov/articles/PMC5553926)), so reminders should be framed around songs, not technique. No controlled study of slowed playback or looping exists at all; the only empirical item is a 2025 analysis of 28 YouTube ear-learning lessons finding that "very few creators or viewers used looping or speed control" ([ScienceDaily](https://www.sciencedaily.com/releases/2025/05/250527124849.htm)). Gamification evidence is engagement-level only.

No vendor publishes its pitch tolerance or timing window; the thresholds below are derived from the research and from open rhythm games, and the report labels them as such. Blanco's "correct" boundary was 50 cents and expert error ~20 cents, which gives the intonation ladder; osu!taiko publishes half-width windows of **GREAT 50 → 20 ms and OK 120 → 50 ms** as difficulty rises from 0 to 10 ([osu!taiko judgement](https://osu.ppy.sh/wiki/en/Gameplay/Judgement/osu!taiko)), which gives the timing ladder. Human baselines bound what can be judged: amateur musicians anticipate the beat by 10–30 ms and non-musicians by 20–80 ms ([Frontiers review](https://www.frontiersin.org/journals/human-neuroscience/articles/10.3389/fnhum.2015.00154/pdf)), and synchronisation breaks down below ~150–200 ms inter-onset intervals ([London et al. 2019](https://jyx.jyu.fi/bitstream/123456789/66341/1/london2019tappingdoesnthelpsynchronizeds.pdf)), so early/late bias is shown as a separate unpenalised indicator, variance is what is scored at first, and fast dhaanto is judged at the beat rather than the subdivision.

The scoring pipeline must keep pitch and rhythm separate. The standard call-and-response pipeline extracts F0 of reference and take, aligns with dynamic time warping and scores deviation, but a 2017 NUS study warns that "DTW alignment on pitch contours ties rhythm scoring to pitch accuracy, so a singer with good timing but off-key pitch can be penalized on rhythm" ([NUS](https://smcnus.comp.nus.edu.sg/archive/pdf/2017-2018/2017_Perceptual_Evaluation_of_Singing_Quality.pdf)); the patented alternative produces separate key-matching and rhythm-matching scores before combining ([US 8,575,465](https://patents.google.com/patent/US8575465)), and reference-free scoring against a semitone grid or the known key removes the need for a teacher contour entirely ([Nakano 2006](https://www.isca-archive.org/interspeech_2006/nakano06_interspeech.pdf); [Hsieh et al. 2025](https://www.isca-archive.org/interspeech_2025/hsieh25c_interspeech.pdf)). For the kaban that means aligning on note or onset level rather than raw F0, scoring intonation per note as median cents from the fitted pentatonic degree with the teacher phrase used only to define the phrase and its rhythm, and scoring rhythm as onset offset after alignment in milliseconds and as a fraction of the beat. Melodics' two published rules — score proportional to closeness to the beat inside the window, a miss resets the streak, scores uncapped and lesson-specific so learners "use your score as a personal benchmark for each lesson" with Platinum as "a checkpoint" ([Melodics scoring](https://support.melodics.com/en/articles/15092017-lesson-scoring)) — and GarageBand's "My Results" toggle that hides errors ([Apple](https://support.apple.com/guide/garageband/see-how-well-you-played-a-lesson-gbndb71d9eec/mac)) are the encouraging frame: show the verdict, default to per-phrase personal best, offer hide-errors review, never penalise rhythm for an intonation miss.

The tonic-first, cycle-first presentation comes from the non-Western tools, which converge on three choices the Western apps lack. Riyaz has Hindustani and Carnatic learners "choose a raag and set a shruti (base note)" and draws the original singer's pitch beside the learner's ([Riyaz](https://riyazapp.com)); Maqam World organises theory around ajnas with a tonic and a ghammaz and teaches iqa'at as a "skeleton" of dum and tak that percussionists ornament ([Maqam World, jins](https://www.maqamworld.com/en/jins.php); [Maqam World, iqa'](https://www.maqamworld.com/en/iqaa.php)); erhu apps grade "each note in cents" with "fretless pitch feedback" ([Soloist Erhu](https://apps.apple.com/app/id6776352481)). For the kaban Learn mode this means set the tonic first, draw every pitch as cents from tonic on a pentatonic lattice using the fitted grid rather than 12-TET note names, and teach rhythm as named cycles with two stroke colours and an optional ornament layer rather than as a time-signature lesson. Because qaraami is pentatonic and avoids quarter tones ([Wikipedia, Music of Somalia](https://en.wikipedia.org/wiki/Music_of_Somalia)), the oud forum's advice to start with maqamat that avoid quarter tones is already satisfied ([Mike's Oud Forums](https://www.mikeouds.com/messageboard/viewthread.php?tid=12356)), and Oud for Guitarists' "Hear a Maqam – Sing a maqam – Know the maqam" ordering gives the cheapest call-and-response step, since the microphone pitch path is the same whether the learner sings or plays ([Oud for Guitarists](https://www.oudforguitarists.com/ear-training-program/)). The only non-Western rhythm trainer with a paper, Uyar and Bozkurt's usul trainer, records a performance, detects onsets and compares their locations to the cycle template, reported as "preliminary test results" ([FMA 2015](https://zenodo.org/records/1211661/files/FMA2015_BurakUyar_FullPaper.pdf)); CompMusic's own report admitted "we have not yet started any formal evaluation" ([CompMusic](https://compmusic.upf.edu/te/node/204)). No non-Western pedagogy tool has published learning outcomes, so a Somali tool that logs per-note cents and per-stroke milliseconds over weeks, with the feedback-off series as the dependent variable, would be the first with measured data in this niche — a legitimate research claim for the application package, provided the logging schema is designed now.

Rhythm trainers in 2025 share four table-stakes features — per-beat subdivisions and accents, a tempo ramp of a set step every N bars, muted "coach" bars that test the internalised pulse, and a drift mode where the click "gently drifts around your target tempo" so the learner holds the true pulse ([Poly Metronome](https://apps.apple.com/us/app/id1449133515); [Takt](https://play.google.com/store/apps/details?id=com.takt.app)) — and the pedagogy literature introduces compound metre as 3/8 before 6/8 with a distinct syllable set rather than by counting six ([Telesco, JMTP](https://journals.ou.edu/jmtp/ojs/ejournal/article/download/904/1795/1815); [Takadimi](https://journals.ou.edu/jmtp/article/download/748/1589/1579)). Because the dhaanto metre is unresolved in the sources (see the next section), the cycle display should render 12 pulses as either 4×3 or 6×2 and let the musician-annotator pick the felt grouping per song. Browser latency sits under all of this: with Safari at ~100 ms and Chrome at ~50 ms round trip ([weblatencytest](https://github.com/gilpanal/weblatencytest)), an uncalibrated ±50 ms window would mis-grade every Safari user, so the same loopback or tap-to-click calibration that Record needs must run before any scored exercise, and `outputLatency` is only a starting estimate ([web.dev](https://web.dev/articles/audio-output-latency)).

Content structure is path → unit → lesson → exercise → song, as Duolingo Music builds it from "Unit 1: Learn the notes C, D, and E" toward full songs with XP, daily quests and a streak ([Duolingo blog](https://blog.duolingo.com/p/fc0b9772-e1f6-4223-9a9f-ebf76b94b047/)) and GarageBand's lessons keep a History graph with a point per complete performance and a High Scores table ([Apple](https://support.apple.com/guide/garageband/gbnd50355d19/mac)). The kaban curriculum skeleton is units by degree set (1-2-3, then add 5, then add 6), each with listen, sing back, play back and play-with-cycle lessons, scored call-and-response exercises, and showcase songs with loop, slow-down and wait mode; the rhythm path runs in parallel from cycle recognition through clap-along with muted bars to oud strokes on the cycle. Rights are the one place the archive is ahead of the industry: Yousician's licensed repertoire is "subject to change" and can be removed ([Yousician](https://support.yousician.com/hc/en-us/articles/360000758937-Why-can-t-I-find-a-popular-song-in-Yousician)), flowkey splits public-domain pieces into a cheaper Classic tier ([flowkey Classic](https://deals.androidauthority.com/sales/flowkey-classic-plan-3-year-subscription)), and the studio's served repertoire — showcase clips, generated reference phrases, the synthesised oud, and musician-recorded phrases under a written consent record — already matches the safest tier, with every item carrying a rights class as the model cards do.

Against the baseline of scale, rhythm and melody lessons with scored practice, the next steps are concrete: insert the calibration step before any scored exercise; replace whatever tolerance is in the scorer with the ladder above and surface early/late bias separately; add wait mode and a 25 %-floor slow-down on decoded buffers; make the tonic and fitted grid the reference and the display one line against one bar; add blind repetitions and store the feedback-off series as the progress metric; frame scores as per-phrase personal bests with a hide-errors toggle; and define the per-attempt log schema (learner id, exercise id, tonic, per-note cents, per-onset ms, feedback on/off, calibration offset, browser) now, because it becomes both the listening-study extension and the dataset's `evaluation` subset.

## The musicology supports a glossary but leaves three disputes the dictionary must show

The primary field sources are better than the Wikipedia-derived picture most apps would start from, and they disagree with it in places the 72-term dictionary should check. Giannattasio's 1984–85 survey with the National Theatre's director divides Somali performance into *gabyid* (composing and performing poetry), *heesid* (singing songs) and *ciyaarid* (play-dancing), with *gabay* naming the chief poetic genre and by extension all the maanso genres from gabay to buraanbur to masafo, *hees* covering life-cycle and work songs plus the "minor" genres wiglo, hirwo, dhaanto and belwo and the new national song heello, *ciyaar* covering ludic dance and possession ritual (saar), and *digri* (dhikr) set apart as "completely extraneous from the idea of music", such that one may not even use the verbs *qaadid* or *heesid* for *qasiidooyin* ([Giannattasio 1988](https://arcadia.sba.uniroma3.it/handle/2307/984)). Hirsi adds the maanso–hees line as the pastoralist view ("light poetry forms that accompanied work") and documents that southern Banaadiri poetry differs markedly in genre and form, with the *hoojis/hooris* fishing couplet and *shirib* bridges in Aweys Geedow's 1968 "Ciyow Biyaha Keen" ([Hirsi 2023](https://wardheernews.com/wp-content/uploads/2023/05/Aweys-Geedow-Nuur-Diinles-Ciyow-Biyaha-Keen-A-Case-Study-By-Ibrahim-Hirsi.pdf)); Kapteijns glosses *hees* as "modern song" with *waddani* patriotic songs as a sub-genre promoted through Radio Mogadishu, Radio Hargeisa and the National Theatre ([Kapteijns 2009](https://www.cambridge.org/core/journals/journal-of-african-history/article/discourse-on-moral-womanhood-in-somali-popular-songs-19601990/8B56054C3458B9805AA848CCC8079B06)).

"Qaraami" itself has three documented senses and the glossary entry should state all three. Giannattasio's catalogue labels a 1985 piece by Xaaji "Baalbaal" as "'Qaraami', tipo di gabay ... ad argomento amoroso", a love-themed poetic type ([Catalogo dei documenti sonori](https://arcadia.sba.uniroma3.it/bitstream/2307/798/1/Catalogo%20dei%20documenti%20sonori%20sulla%20musica%20somala.pdf)); Jama Musse Jama's 2023 monograph uses it as a period label for Somaliland's oldest modern music "mainly from the 1940s to the mid-1960s", later meaning "old-time good music", and contains the first transcriptions of Beerdillaacshe, Carwo, Murug, Nugul and Aroor ([African Books Collective](https://www.africanbookscollective.com/books/qaraami)); Geeska and Harvard's Loeb library record the everyday sense of "old Somali songs" and love songs that "can also express love of family, nature, or God" ([Geeska](https://www.geeska.com/en/making-hudeidi); [Loeb Music blog](https://archive.blogs.harvard.edu/loebmusic/2021/05/06/hudeidi-the-somali-king-of-oud-another-sad-casualty-of-covid-19/)). The Arabic root *gharām* (love) is asserted only in book blurbs; no dictionary was fetched, so the entry should say "etymology commonly given as Arabic *gharām*, unverified". The balwo → heello → new Somali song sequence is consistent across Giannattasio, Johnson (via Wikipedia) and Bashir Goth, and the firm primary dates are **1943 for balwo** (Qarshe's own 1985 account: "genere creato nel 1943 da Cabdi Shineemo"), **1948 for the kaban's introduction** (Giannattasio 1987) and **1949 for a political heello** ([Catalogo](https://arcadia.sba.uniroma3.it/bitstream/2307/798/1/Catalogo%20dei%20documenti%20sonori%20sulla%20musica%20somala.pdf); [Giannattasio 1987](https://arcadia.sba.uniroma3.it/handle/2307/736)); Wikipedia's claim that balwo "developed in the 1920s" contradicts this and should be marked as the minority account ([Wikipedia, Somali literature](https://en.wikipedia.org/wiki/Somali_literature)). Goth's narrative — Arabic songs from Aden on phonographs dominating 1939–43, the *kabacad* "clean shoes" groups, Abdi Sinimo's first sound from a kerosene tin, the third Balwo Band as first to use the oud, Khadiija Balwo among the first women performers — is journalistic but detailed enough to cite as such ([Music in Africa](https://www.musicinafrica.net/node/25169)).

Dhaanto is the first live dispute. Xaange's informant says it "developed from the Hurbo" and "first appeared in the '30s of the last century as a dancing song among ... the camel-herders in the western part of the country", with verses interchangeable with wiglo and only the melodies differing ([Xaange 2014](https://romatrepress.uniroma3.it/wp-content/uploads/2019/05/folk-xapu.pdf)); Wikipedia, citing Johnson, says it was "revived in the late 19th century by the Dervish Movement" and often sung on horseback ([Wikipedia, Dhaanto](https://en.wikipedia.org/wiki/Dhaanto)); both cannot be true as stated. Its rhythm is described only verbally and inconsistently: Dur-Dur Band Int. calls the groove "strongly accented on the off-beat" and insists it is not reggae ([Dur-Dur Band Int.](https://dur-durbandint.bandcamp.com)), Giannattasio transcribes three salutation couplets in 2/8 and 3/8 and records a four-phase dhaanto session with jerrycan drum and handclaps ([Giannattasio 1988](https://arcadia.sba.uniroma3.it/handle/2307/984)), a dance tutorial sets it in 4/4 with claps on 1 and 3 ([Medium](https://medium.com/@thebluestars/dhaanto-dance-steps-d17b1ab0fa4f)), and the Somali Museum of Minnesota says it "is inspired by the camel" ([TPT](https://www.tptoriginals.org/somali-traditional-dance-101/)). The glossary should say "metre contested; off-beat accent attested; 2/8 and 3/8 in field transcriptions; dance tutorials count 4/4", and the rhythm lesson should present the cycle at both groupings. The second dispute is the kaban: Giannattasio's "liuto a tasti yemenita" (fretted Yemeni lute) and the Somali keyword *gambuus* on Qarshe's 1984 scale demonstration suggest the first instrument adopted was a *qanbūs*-type lute rather than the modern fretless oud ([ArcAdiA 2307/1056](https://arcadia.sba.uniroma3.it/handle/2307/1056); [Giannattasio 1987](https://arcadia.sba.uniroma3.it/handle/2307/736)), and no fetched source supports the *kamān* ("violin") etymology; the entry should describe the modern kaban as the oud, note the 1948 "Yemeni lute" wording, and drop the unsupported etymology. The third is terminology drift between the field data and Wikipedia's instrument list: Giannattasio's 1987 classification has *malkad/siimbaar* as trumpets and *teneg* as a struck tin, where Wikipedia (from Abdullahi 2001) lists them as flutes and a xylophone ([Giannattasio 1987](https://arcadia.sba.uniroma3.it/handle/2307/736); [Wikipedia, Music of Somalia](https://en.wikipedia.org/wiki/Music_of_Somalia)), and *durbaan* is the generic word for cylindrical drums while *daf* is the frame drum or tambourine in Qarshe's 1985 ensemble, so the studio's "frame-drum durbaan" naming conflates two instruments and should be corrected to *daf* or qualified.

The instrument section gives the glossary its organising principle: Somali thinking divides instruments by the verb used to play them, *yeerin* ("make it sound": wind instruments and the camel bell *koor*) against *tumid* ("strike": every string instrument including the *shareero* lyre and the *kaban*, all drums, handclaps *sacab*, foot-stamping *jaan*, the clappers *shanbal* and *sharaq*), with *jiib* (multivocal singing) and *jaan* transferred to modern bands "to distinguish the melodic from the rhythmic sections" ([Giannattasio 1988](https://arcadia.sba.uniroma3.it/handle/2307/984)). The *shareero* is a six-string bowl lyre tuned D4 D3 B3 A3 G3 E3 whose name "seems linkable to the Semitic root *knr*" ([Giannattasio 1987](https://arcadia.sba.uniroma3.it/handle/2307/736)); the pitch classes D E G A B form an anhemitonic pentatonic set, which is this report's inference from the caption rather than Giannattasio's statement, but it is the one piece of instrument evidence that corroborates the pentatonic claim the studio's scale fitter relies on, alongside Qarshe's recorded "Scala diatonica vs. scala pentatonica" demonstration of December 1984. The *haan* is both a milk vessel and, with a wet kid skin stretched over its mouth, the women's drum of the dance of the same name, which men may only watch ([Xaange 2014](https://romatrepress.uniroma3.it/wp-content/uploads/2019/05/folk-xapu.pdf)). The genre and dance terms with field-source backing — *wiglo* as "one of the oldest genres" with no accompaniment and vocable refrains, *hirwo* as its 1950s danced form, *batar* as a nationwide dance with the "ta-tam-ta-tam" pattern, *shirib* as both a northern dance-song and a southern Banaadiri verse form, *haan*, *baarcadde*, *buraanbur* as the women's "lighter measure (miisaan)" counterpart to gabay with sub-genres hoyal, hoobeeyo and sitaat ([Wikipedia, Buraanbur](https://en.wikipedia.org/wiki/Buraanbur)), *sittaat* as women's praise songs for the mothers of the believers with a stick-played *durbaan*, *jibbo* climax and *taraaraysi* pre-birth ritual ([Somaliland Chronicle](https://www.somalilandchronicle.com/2022/08/01/sitaad-the-somali-womens-traditional-spiritual-gathering/)), the possession repertoires *saar*, *mingis*, *nuumbi* with the *shareero*, and *xayaad* — are enough for a glossary that cites a page per entry. Terms with only names and journalistic notes (*saylici*, *wilwile*, *jaandheer*, *xoogweyn*, *saddexley*, *kabeebey*) and terms appearing nowhere in the fetched sources (*kabanle*) must carry a "tentative" status. Johnson's *Heelloy* was not readable, so the heello's internal periodisation and the function of the *heellooy heelleellooy* refrain are gaps, as is the melody–metre relation that Orwin's quantitative-metre work and Hayward and Lewis's "Music, metre and Somali poetry" address ([Orwin 2018](https://unora.unior.it//retrieve/handle/11574/199777/90124/Orwin%20-%202018%20-%20Metre%20and%20'extrametricality'%20in%20the%20geeraar.pdf); [Hayward & Lewis](https://www.taylorfrancis.com/chapters/mono/10.4324/9780203985397-13/music-metre-somali-poetry-hayward-lewis)).

The next step for the dictionary is an audit, not an expansion: check each of the 72 entries against Giannattasio 1987/1988, the catalogue and Xaange, add `status` (accepted/tentative), `source` and `notes` fields, record the three disputes as disputes, fix the daf/durbaan and malkad/teneg conflicts, and only then hand the file to a Somali musician for review — which is the CARE "authority to control" step the dataset card will need to describe. The lesson text should use the 1972 orthography consistently (c = /ʕ/, x = /ħ/, dh = /ɖ/, doubled long vowels) with the variants the sources use in parentheses.

## Publish the dataset as an honest card around rights-clean subsets

The Hub mechanics are settled and fast. A dataset repo is a Git repo whose `README.md` YAML header both documents and configures it: `configs` lists each subset with `config_name` (required even for one subset), `data_dir` or `data_files` with split paths, `default: true` for the subset the viewer shows first, and `dataset_info` declares feature types ([HF manual configuration](https://huggingface.co/docs/hub/datasets-manual-configuration)). For 15–30 s clips the documented recommendation is raw audio files plus a `metadata.jsonl` with a `file_name` column of relative paths, because Parquet is advised only for audio under about 1 MB per file ([HF audio datasets](https://huggingface.co/docs/hub/datasets-audio); [HF uploading](https://huggingface.co/docs/hub/datasets-adding)); tabular records go in Parquet or JSONL, with any JSONL kept under 10 MB or converted, since larger text files silently fail to upload through the UI ([datasets docs](https://huggingface.co/docs/datasets/upload_dataset)). Loading scripts are gone: `datasets` 4.0 removed them and `trust_remote_code` ([datasets 4.0.0](https://github.com/huggingface/datasets/releases/tag/4.0.0)), and the Hub's storage policy says datasets needing custom code "often end up with limited reuse" ([HF storage limits](https://huggingface.co/docs/hub/storage-limits)). The Data Studio viewer is on by default for public repos and auto-converts the first 5 GB to Parquet with search, filters and a DuckDB SQL console ([HF Data Studio](https://huggingface.co/docs/hub/datasets-viewer)); `upload_folder` with Xet streams, splits large folders into several commits and resumes on re-run ([huggingface_hub upload guide](https://huggingface.co/docs/huggingface_hub/guides/upload)); tags are created with `create_tag`, and `load_dataset(repo, config, split, revision)` pins a version ([huggingface_hub repository guide](https://huggingface.co/docs/huggingface_hub/guides/repository)). Two irreversibilities set the order of operations: `private=True` works only on first creation, and a DOI, minted per revision through DataCite, locks delete, rename and visibility changes behind a support ticket ([HF DOI](https://huggingface.co/docs/hub/doi)). So: create private, upload, verify every config renders in the viewer, fix YAML with `metadata_update`, tag `v1.0.0`, flip to public (or `gated="auto"` if contact details are wanted), then generate the DOI, then confirm `/api/datasets/<repo>/croissant` returns the licence and record sets, which the Hub builds automatically from the Parquet conversion and card metadata ([HF Croissant](https://huggingface.co/docs/dataset-viewer/croissant)). Symbolic files (MusicXML, MIDI, PDF) are hosted but "may not be recognized by the Hub" as viewer columns, so they ship as plain files under `symbolic/` with an `index.jsonl` manifest that can itself be a config, mirroring how MAESTRO ships MIDI beside a metadata CSV ([HF uploading](https://huggingface.co/docs/hub/datasets-adding); [MAESTRO](https://magenta.tensorflow.org/datasets/maestro)). The language field takes `so` (ISO 639-1, as the Somali parallel corpus declares) or `som` (639-3, as FLEURS does), and a SomaliWeb survey counted roughly 250 "somali" datasets on the Hub in April 2026, mostly speech, translation and instruction data, with no Somali music-terminology dataset found ([tufaax README](https://huggingface.co/datasets/tufaax/en-so-parallel-clean-8k/raw/main/README.md); [google/fleurs](https://huggingface.co/datasets/google/fleurs/raw/main/README.md); [SomaliWeb](https://arxiv.org/pdf/2605.18232)).

The card is where the dataset earns "reference-grade", and its shape is already prescribed. The Hub's template mirrors Gebru et al.'s seven Datasheets sections — motivation, composition, collection, preprocessing, uses, distribution, maintenance — with slots for inter-annotator statistics, personal and sensitive information, out-of-scope uses and a contact ([datasetcard template](https://raw.githubusercontent.com/huggingface/huggingface_hub/main/src/huggingface_hub/templates/datasetcard_template.md); [Datasheets](https://ar5iv.labs.arxiv.org/html/1803.09010)). The core of this card is an "Excluded material" subsection that names each source class the archive holds but does not ship — the Harvard/Aryette cassettes, the Ahmed Ilkacase oud recordings, the `.band` imports, the internet-scraped oud and mix sets — the reason (rights per `DATA_PROVENANCE.md`), and what is present that was influenced by them, namely adapters trained on them. There is precedent for shipping derived artefacts rather than audio: MusicCaps distributes "No audio", only YouTube IDs and timestamps ([google/MusicCaps](https://huggingface.co/datasets/google/MusicCaps)), and the CompMusic makam dataset states "Audio: Not distributed for copyright reasons" and ships pitch tracks keyed by MusicBrainz IDs instead ([mirdata OTMM loader](https://raw.githubusercontent.com/mir-dataset-loaders/mirdata/master/mirdata/datasets/compmusic_otmm_makam.py)). Sturm's GTZAN audit — 50 exact repetitions, 93 mislabelings, Bob Marley over a third of Reggae — is the lesson that undocumented faults, not faults, destroy comparability ([Sturm 2013](https://ar5iv.labs.arxiv.org/html/1306.1461)), so the card must state the project's own 2026-09-19 diagnosis that the SFT adapters add noise (spectral flatness 0.02–0.07 against 0.005 for the base model) and the 245 duplicate training rows the proof-of-generation work found. MAESTRO asks users to state the version because V1–V3 are incompatible ([MAESTRO](https://magenta.tensorflow.org/datasets/maestro)), MedleyDB keeps an `ERRATA.md` ([marl/medleydb](https://github.com/marl/medleydb)), and vocadito publishes two annotators' agreement (note F 0.64 ± 0.13, F-no-offset 0.74 ± 0.09) with anonymised singer IDs ([vocadito](https://ar5iv.labs.arxiv.org/html/2110.05580)); each of these becomes a sentence in the card. Model-output provenance has no community standard, so the per-row schema is an inference assembled from Datasheets' "is the software available" and "was the raw data saved" questions and from the generators' own disclosure guidance: `model_id`, `model_revision`, `adapter_name`, `adapter_sha256`, `adapter_step`, `prompt`, `seed`, `duration_s`, `sampling_rate`, `cfg`, `temperature`, `top_k`, `generation_date`, `generator_commit`, `postprocessing`, the already-computed metrics (`spectral_flatness`, `pcs`, `voiced_ratio`, `mert_nn_sim`), `rights_class`, `licence` and `listening_votes`, with the seed-determinism proof linked. MusicGen's card says the model "should not be used on downstream applications without further risk evaluation" and ACE-Step asks users to "clearly disclose AI involvement" and warns of "unintentional copyright infringement due to stylistic similarity" ([facebook/musicgen-large](https://huggingface.co/facebook/musicgen-large); [ACE-Step README](https://github.com/ace-step/ACE-Step)); both belong verbatim under Bias, Risks and Limitations.

CARE is the layer FAIR lacks and the one a diaspora-built Somali dataset needs. Carroll et al. define collective benefit, authority to control, responsibility and ethics as a complement to FAIR that extends from data to "people" and "purpose" ([Carroll et al. 2020](https://datascience.codata.org/articles/10.5334/dsj-2020-043)), paraphrased by the ARDC as data ecosystems designed so communities derive benefit, a responsibility to share how data are used, and community wellbeing as the primary concern at every stage ([ARDC](https://ardc.edu.au/resource/the-care-principles/)). In the card that means stating who benefits, who controls, a named contact and takedown route, and how community members can object or contribute; for the glossary and any musician-corrected packs it means recording who contributed (role rather than personal data unless agreed), when, and under which licence. The twelve CARE sub-principles, Bender and Friedman's Data Statements and Local Contexts' TK Labels were not retrieved this session and should be read before the card is final.

Licensing has to be per subset, and the AI-output question has to be stated rather than papered over. The Hub accepts `license` as a list and provides identifiers for every option, with `other` requiring a `LICENSE` file and `license_name` ([HF licenses](https://huggingface.co/docs/hub/repositories-licenses)). Creative Commons confirms that CC licences "can be used on databases" and that the 4.0 suite licenses sui generis database rights under the same conditions, which makes CC BY 4.0 sufficient for annotations and metadata without ODC-By ([Creative Commons FAQ](https://creativecommons.org/faq/)). Community norms by subset type are consistent: vocadito, NSynth and Slakh2100 use CC BY 4.0 for own recordings and synthesis ([Zenodo 5578807](https://zenodo.org/records/5578807); [NSynth](https://magenta.tensorflow.org/datasets/nsynth); [Zenodo 4599666](https://zenodo.org/records/4599666)); MusicCaps and Song Describer use CC BY-SA for captions ([google/MusicCaps](https://huggingface.co/datasets/google/MusicCaps)); MAESTRO, MedleyDB and Saraga use CC BY-NC-SA where third-party recordings are involved ([Saraga](https://mtg.github.io/saraga/)); MTG-Jamendo and FMA map code, metadata and audio to different licences with per-track licence files ([MTG/mtg-jamendo-dataset](https://github.com/MTG/mtg-jamendo-dataset); [mdeff/fma](https://github.com/mdeff/fma)). The complication is the generated audio. MusicGen's weights are CC-BY-NC 4.0 and neither the card nor the audiocraft README says anything about outputs ([facebook/musicgen-large](https://huggingface.co/facebook/musicgen-large); [audiocraft](https://github.com/facebookresearch/audiocraft)); the ACE-Step 1.5 Hub card is MIT and says "You can strictly use the generated music for commercial purposes" while the GitHub README says Apache-2.0, a conflict resolved only by reading the LICENSE in the exact checkpoint used ([ACE-Step/Ace-Step1.5](https://huggingface.co/ACE-Step/Ace-Step1.5)). Beneath both sits the US Copyright Office's January 2025 report that outputs are protected only "where a human author has determined sufficient expressive elements" and that "the mere provision of prompts" does not qualify ([USCO](https://www.copyright.gov/newsnet/2025/1060.html)), which means a CC licence on prompt-driven clips may have nothing to attach to and functions as terms of use. The honest card says exactly that, claims rights only in selection, arrangement, metadata, glossary, annotations and synthesis code, and never uses `-ND` (it blocks the resampling and feature extraction that make a dataset useful) or `-SA` on the benchmark.

| Subset | Content | Licence | Rationale |
| --- | --- | --- | --- |
| `glossary` | 72+ Somali–English terms with sources and status | CC BY 4.0 | own work; keeps attribution the app needs (CC0 defensible per PanLex precedent) |
| `evaluation` | listening-study trials, A/B scores, Qormada results | CC BY 4.0 | own records, anonymised listener IDs |
| `synth_benchmark` | synthetic Somali-style audio + note ground truth | CC BY 4.0 | own synthesis (NSynth/Slakh precedent) |
| `symbolic` | engraved score, MusicXML, MIDI | CC BY 4.0 | own engraving |
| `generated` (MusicGen adapters) | clips with full provenance | CC BY-NC 4.0 + research-use note | weights CC-BY-NC; LoRAs trained on rights-restricted audio; copyrightability doubtful |
| `generated` (ACE-Step clean-oud LoRA) | clips with full provenance | CC BY 4.0 (if the checkpoint LICENSE confirms) | card permits commercial use; LoRA trained on own `clean_oud` |

The benchmark subset needs splits and conventions, not more data. Entity-level splits are the norm — MAESTRO keeps each composition in one split, NSynth keeps instruments disjoint, Slakh moved duplicate-MIDI tracks to an `omitted` directory, and Sturm showed artist filtering lowers every GTZAN system by up to 25 points ([MAESTRO](https://magenta.tensorflow.org/datasets/maestro); [NSynth](https://magenta.tensorflow.org/datasets/nsynth); [Zenodo 4599666](https://zenodo.org/records/4599666); [Sturm 2013](https://ar5iv.labs.arxiv.org/html/1306.1461)) — so `synth_benchmark` carries a `split` column by melody family and `generated` by prompt and seed family. Notes are stored as `onset_s, offset_s, pitch_hz` (plus `midi` for readability) because `mir_eval.transcription` takes interval arrays and Hz with defaults of **50 ms onset tolerance, 50 cents pitch tolerance, offset tolerance of 20 % of duration with a 50 ms floor**, and bipartite matching, and its `evaluate()` always reports both `F-measure` and `F-measure_no_offset` ([mir_eval](https://mir-eval.readthedocs.io/latest/api/transcription.html)). The shipped `scripts/eval_notes.py` should call those defaults and print both, and the `results/` table should carry the Qormada baselines already on record (vocadito note F1 0.687 against the annotators' 0.740; synthetic set F1 0.820) with the dataset tag they were computed on; vocadito's finding that quantising f0 to semitones yields only F 0.20 is the reason notes, not just pitch tracks, are the ground truth ([vocadito](https://ar5iv.labs.arxiv.org/html/2110.05580)). The Ethiopian kiñit dataset — 600 recordings in four pentatonic modes labelled by five expert judges, published in PLoS ONE with a 95 % baseline ([arXiv 2201.08448](https://arxiv.org/abs/2201.08448)) — shows a pentatonic-mode task with controlled ground truth is publishable, which makes the synthetic benchmark credible as a first Somali-mode benchmark provided the card says synthetic and gives the recipe. If FAD is ever reported, fadtk's guidance applies: state the embedding (`clap-laion-music` for music), the reference set and its licence, use `--indiv` to flag outliers, and do not compare against VGGish/MusicCaps numbers from other papers, since fadtk advises against MusicCaps as a default reference and calls VGGish classification-oriented ([microsoft/fadtk](https://github.com/microsoft/fadtk)). Hub `EvalResult` records point at a dataset by config, split and git revision, which is the leaderboard plumbing for free ([huggingface_hub cards](https://huggingface.co/docs/huggingface_hub/package_reference/cards)).

The metadata schema should be tradition-native in the CompMusic manner. Saraga ships tonic in Hz, pitch tracks as tab-separated time and frequency, cycle boundaries (sama), sections as `start, duration, label`, melodic phrases with solfège labels, and JSON metadata with rāga, tāla, form and MusicBrainz ID, all under CC BY-NC-SA 4.0 ([mirdata Saraga loader](https://raw.githubusercontent.com/mir-dataset-loaders/mirdata/master/mirdata/datasets/saraga_carnatic.py); [CompMusic corpora](https://compmusic.upf.edu/corpora)). The Somali equivalent, one row per clip, is `tonic_hz`, `scale_name_so` and `scale_name_en` as glossary concept IDs, `scale_degrees_cents` (the fitted grid), `metre` and `rhythm_name_so` (with the dhaanto grouping left to the annotator), `tempo_bpm`, `form_so`/`form_en`, `instrumentation` as glossary IDs, `lyrics_language`, `source_type` (`generated`, `synthetic`, `symbolic`) and the provenance fields above, with section and phrase annotations in the Saraga `start, duration, label` convention so a mirdata-style loader is trivial. The glossary itself is a flat table keyed like PanLex's `meaning` join column ([cointegrated/panlex-meanings](https://huggingface.co/datasets/cointegrated/panlex-meanings/raw/main/README.md)): `concept_id`, `term_so`, `term_so_variants`, `term_en`, `pos`, `domain`, `definition_so`, `definition_en`, `example_so`, `example_en`, `related_concept_ids`, `source`, `source_type`, `contributor_id`, `status`, `notes`, `licence`, with IDs kept stable across versions so audio rows can reference them, and an optional TBX-Basic export in `docs/` for terminologists since TBX is ISO 30042:2019 but the Hub will not render it ([tbxinfo.net](https://www.tbxinfo.net/)). The unverified items are the exact `task_categories` identifiers (`text-to-audio` and `audio-classification` are believed valid but were not checked), the Hub's DOI prefix, whether `CITATION.cff` is parsed by the Hub, and whether `so` and `som` may appear together.

Six weeks from Monday 10 November runs to Friday 18 December. Three cross-cutting rules hold across every week. The rights gate stays absolute, so nothing in weeks 3–5 may add a served clip that the `check-public-audio-rights` gate would reject, and the dataset's `generated` subset is assembled only from clips whose adapters' rights class permits it. Every scored exercise and every take runs behind the calibration from week 1, because the WAC 2025 numbers make an uncalibrated ±50 ms window wrong on Safari by design. And nothing is reported as done without the artefact — the calibration shows its measured offset, the Learn loop shows a feedback-off series in a log file, the dataset shows its viewer, tag, DOI and Croissant endpoint — which is the same standard the research programme already applies to listening sets.

## Conclusion

The research reframes the studio's position: the parts QaraamiGen cannot buy from BandLab or Apple — a scale model fitted in cents from real qaraami recordings, a rhythm model that admits the dhaanto metre is contested, a glossary that cites a page per term and marks what is tentative, and a learning loop whose progress metric is accuracy with the feedback off — are exactly the parts the mainstream products do not have, and they are cheaper to build than the engine work that would merely match them. Apple's seventeen 12-TET scales and twelve-cent tuning table, and GarageBand's major-or-minor song key, mark the ceiling of the biggest player's cultural reach; a per-scale cent grid as first-class project data clears it in a week. The non-Western pedagogy tools have presentation right and evaluation absent, so the per-attempt log designed now is both the product's progress graph and the first measured learning data in this niche.

The dataset follows the same logic. Its value to researchers is not volume but the combination of honest provenance for every generated clip, a synthetic benchmark with `mir_eval`-ready ground truth and leakage-safe splits, listening-study records with the protocol as columns, and the first Somali music-terminology table on the Hub — assembled around an "Excluded material" section that says plainly which archives shaped the adapters and why none of their audio is shipped. Minting the DOI only after the repo is public, stating that prompt-driven audio may not be copyrightable, and recording a CARE-style contact and takedown route are the three moves that turn a data dump into something a reviewer, or an admissions committee, can cite.
